本篇讲软件怎样组织、各部分如何调用、关键文件和函数做什么、怎样修改和重建。设计取舍和备选方案见 [方案设计](<方案设计.md>)；操作见 [01 使用指南](<01 使用指南.md>)。

## 1. 软件要解决什么问题

把「本地 K 线文件 → 因子 → 机器学习模型 → 样本外预测 → 按 A 股规则回测 → 选股」这一整条流程做成一个双击即用的桌面应用，让学习者能在自己的数据上反复做实验，又不容易犯「未来函数」「幸存者偏差」这类错误。

技术形态：**Python 计算引擎 + 本机网页界面**。引擎和一个只监听 `127.0.0.1` 的 HTTP 服务跑在同一个进程里；界面是普通网页（原生 JavaScript + ECharts），由 pywebview 放进系统自带的网页组件窗口（Windows 用 WebView2，macOS 用 WebKit）。用 PyInstaller 打包，用户不需要装 Python。

## 2. 架构图

```text
┌──────────────────────────── 一个进程：QuantLab（Windows: QuantLab.exe / macOS: QuantLab.app） ────────────────────────────┐
│                                                                                                                        │
│  主线程：app.py  main()                                                                                                 │
│   ├─ 解析参数 → data_dir() → serve()  ──────────────┐                                                                   │
│   ├─ run_window()：pywebview 窗口（WebView2/WebKit） │  失败 → run_browser()：系统默认浏览器                               │
│   └─ 退出：shutdown() 取消任务 → 结束子进程 → 关端口   │                                                                   │
│                                                      ▼                                                                  │
│  线程 "http"：server.py  ThreadingHTTPServer(127.0.0.1:随机端口)                                                         │
│   ├─ GET  静态文件 web/index.html, app.js, markdown.js, style.css, vendor/echarts.min.js                                │
│   ├─ GET  /api/status /api/catalog /api/runs /api/run /api/bars …（读）                                                 │
│   ├─ GET  /api/docs /api/doc /api/doc-asset /api/sources /api/source /api/source.zip  ← guide.py（使用指南）              │
│   ├─ GET  /api/processes                                                             ← sysinfo.py（运行状态）              │
│   └─ POST /api/import /api/demo /api/run/start /api/factors …（写，需令牌）──┐                                            │
│                                                                             ▼                                            │
│  线程 "job-*"：jobs.py  Jobs.start()  同一时间只跑一个，带进度/日志/取消                                                    │
│   └─ experiment.run() ─→ dataset.build() ─→ features / masks                                                            │
│                       ─→ trainer.walk_forward() ─→ models（LightGBM / sklearn）                                         │
│                       ─→ evaluate（IC、分层）─→ backtest.run()（A 股规则）─→ metrics                                     │
│                       ─→ Runs 保存结果                                                                                   │
│                                                                                                                        │
└───────────────┬────────────────────────────────────────────────────────────────────────────────────────────────────────┘
                │ 读写
                ▼
   数据目录（Windows %LOCALAPPDATA%\QuantLab\，macOS ~/Library/Application Support/QuantLab/）
     datasets/<id>/bars.parquet, meta.json     runs/<id>/…     quantlab.log     webview/

   安装目录里的只读资源：quantlab/web/（界面）  projectdocs/（README + docs/）  projectsrc/QuantLab-source.zip（手写源码）
```

要点：

- **没有独立后台进程**。HTTP 服务、计算任务都是主进程的线程，所以关窗退出时一起结束；崩溃时也不会留下后台。
- Windows 上 WebView2 会启动若干 `msedgewebview2.exe` 子进程，属于窗口，「运行状态」里逐个列出。
- 界面只通过 HTTP 接口和引擎交互；命令行 `cli.py` 不经过 HTTP，直接调用同一套引擎函数，共用数据目录。

## 3. 模块组成

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 启动 | `run.py` | 源码运行入口，调用 `quantlab.app.main()` |
| 启动 | `quantlab/app.py` | 参数解析；开窗口或浏览器；日志；`shutdown()` 退出收尾；`--selftest` 自检 |
| 服务 | `quantlab/server.py` | `App`（把引擎包装成接口）、`make_handler`（路由、令牌校验、防 DNS 重绑定）、`serve()` |
| 服务 | `quantlab/jobs.py` | 后台任务：单任务、进度、日志、取消（`Cancelled` 异常） |
| 服务 | `quantlab/guide.py` | 使用指南的资料：文档清单与读取、附件、源码白名单、源码 zip |
| 服务 | `quantlab/sysinfo.py` | 进程与内存采样（psutil；没有时读 `/proc`）；退出时结束子进程 |
| 服务 | `quantlab/paths.py` | 数据目录（按平台）、打包资源目录 |
| 数据 | `quantlab/data/readers.py` | 读各种 K 线文件，统一列名和单位 |
| 数据 | `quantlab/data/adjust.py` | 不复权数据的除权识别与复权因子估算 |
| 数据 | `quantlab/data/store.py` | 数据集导入、增量合并、parquet 存储；`Panel` 宽表 |
| 数据 | `quantlab/data/demo.py` | 生成模拟 A 股演示数据 |
| 规则 | `quantlab/market.py` | 代码规范化、板块识别、涨跌停幅度 |
| 规则 | `quantlab/masks.py` | 股票池、可买、可卖掩码；未来收益标签 |
| 特征 | `quantlab/features.py` | 73 个因子的注册表（`@feature` 装饰器） |
| 样本 | `quantlab/dataset.py` | 决策日 × 股票池 → 样本矩阵 `Samples`，截面标准化，缓存 |
| 模型 | `quantlab/models.py` | 模型注册表：统一 `fit / predict / importance` |
| 训练 | `quantlab/trainer.py` | 滚动训练（walk-forward）+ 隔离带 + 最终模型 |
| 评估 | `quantlab/evaluate.py` | IC、RankIC、ICIR、分层收益、单因子检验 |
| 回测 | `quantlab/backtest.py` | A 股规则组合回测 |
| 指标 | `quantlab/metrics.py` | 收益/风险/交易统计、月度表 |
| 流程 | `quantlab/experiment.py` | 一次实验的完整流程与结果保存（`Runs`） |
| 配置 | `quantlab/config.py` | 默认配置、合并与校验 |
| 命令行 | `quantlab/cli.py` | `demo / import / run / factors / list` 子命令 |
| 界面 | `quantlab/web/index.html` | 页面结构：导航、顶部栏（缩放）、各页面 |
| 界面 | `quantlab/web/app.js` | 页面逻辑：调用接口、画图、缩放、运行状态、使用指南 |
| 界面 | `quantlab/web/markdown.js` | 自写的小型 Markdown 渲染器（不依赖网络） |
| 界面 | `quantlab/web/style.css` | 样式 |
| 打包 | `packaging/build.py` | PyInstaller 打包；Windows 生成安装程序和 zip，macOS 生成 `.app` 和 `.dmg` |
| 打包 | `packaging/installer.nsi` | Windows 安装程序脚本（NSIS） |
| 打包 | `packaging/make_icon.py` | 画应用图标 |
| 测试 | `tests/test_core.py` | 核心逻辑测试（含因子截断一致性：检查有没有未来函数） |
| 测试 | `tests/test_guide.py` | 使用指南、源码白名单、进程接口、退出释放端口 |

第三方（不算手写源码）：`quantlab/web/vendor/echarts.min.js`（ECharts，Apache-2.0）；Python 依赖见 `requirements.txt`。

## 4. 调用链

### 一次实验

```text
界面「开始实验」 app.js startJob('/api/run/start', cfg)
  → server.py do_POST  校验 Host/Origin/令牌
  → App.start_run → Jobs.start('run', …) 新线程
     → experiment.run(store, runs, cfg, progress)
        → config.normalize(cfg)               # 合并默认值并校验
        → dataset.build(store, cfg)           # store.panel → features 计算 → masks → 截面标准化 → Samples
        → trainer.walk_forward(samples, cfg)  # plan_folds → 每段 models.REGISTRY[...].fit/predict → 样本外预测
        → evaluate.ic_series / group_returns
        → backtest.run(samples, pred, cfg['backtest'])
        → metrics → Runs 写 runs/<id>/
界面每秒轮询 /api/job 显示进度 → 完成后打开「实验结果」 → /api/run?id=…
```

### 使用指南

```text
导航「使用指南」 app.js loadGuidePage
  → /api/docs     guide.list_docs()      # docs/ 编号文档 → README → 其余文档
  → /api/sources  guide.Sources.list()   # 源码运行：按 SRC_PATTERNS 扫描；打包版：读内置 zip
  → 点文档  /api/doc?path=…   → markdown.js Markdown.render() → 相对链接改成应用内跳转，图片走 /api/doc-asset
  → 点源码  /api/source?path=… → 带行号显示
  → 下载    /api/save-source（窗口模式另存为） 或 /api/source.zip（浏览器下载）
```

所有路径都先和白名单比对，不在清单里的一律 404，所以 `../` 之类的路径穿越读不到任何文件。

### 运行状态与退出

```text
「运行状态」每 3 秒 → /api/processes → App.process_status → sysinfo.processes()
   psutil.Process(本进程) + children(recursive=True) → PID、RSS/工作集 → MiB

关窗 / ⌘Q / Alt+F4 → pywebview 窗口 closed 事件 → quit_event.set()；webview.start() 返回
   → app.py finally: shutdown()
        Jobs.cancel()（最多等 5 秒） → sysinfo.stop_children()（terminate，3 秒后 kill）
        → httpd.shutdown() + server_close()（释放端口）
        → 若计算线程卡在原生代码里仍未结束 → os._exit(0) 强制结束进程
```

## 5. 关键函数

| 函数 | 位置 | 做什么 |
| --- | --- | --- |
| `main()` | `app.py` | 入口：参数、日志、启动服务线程、开窗口/浏览器、退出收尾 |
| `run_window()` / `run_browser()` | `app.py` | 窗口模式 / 浏览器模式；浏览器模式页面关闭 10 分钟且无任务时退出 |
| `shutdown()` | `app.py` | 退出收尾：取消任务、结束子进程、关闭端口；可重复调用 |
| `make_handler()` | `server.py` | 所有 HTTP 路由；POST 需要令牌 `X-QuantLab-Token` |
| `Jobs.start()` / `cancel()` | `jobs.py` | 后台任务；进度回调里检查取消标志 |
| `DataStore.import_path()` | `data/store.py` | 扫描文件夹 → 读取 → 清洗 → 复权 → 合并 → 写 parquet |
| `dataset.build()` | `dataset.py` | 生成样本矩阵（带缓存） |
| `walk_forward()` | `trainer.py` | 滚动训练，训练集与测试集之间留标签长度的隔离带 |
| `backtest.run()` | `backtest.py` | 逐日撮合：T+1、一手 100 股、费用、涨跌停/停牌不能成交、止损、退市清算 |
| `experiment.run()` | `experiment.py` | 串起整个实验并保存 |
| `list_docs()` / `read_doc()` | `guide.py` | 文档清单（白名单）与读取 |
| `Sources` | `guide.py` | 源码清单、读取、zip；打包版读 `projectsrc/QuantLab-source.zip` |
| `processes()` / `stop_children()` | `sysinfo.py` | 进程内存采样；退出时结束子进程 |
| `Markdown.render()` | `web/markdown.js` | Markdown → HTML（先转义，不放行原始 HTML） |
| `setZoom()` | `web/app.js` | 设置缩放（CSS zoom）、更新按钮禁用状态、保存、重绘图表 |

## 6. 源码阅读路线

1. `quantlab/app.py` → `quantlab/server.py`：先弄清进程里有什么、界面怎么和引擎说话。
2. `quantlab/experiment.py` 的 `_run()`：一次实验的骨架。
3. 顺着骨架读 `dataset.py` → `features.py`（挑几个因子）→ `masks.py` → `trainer.py` → `backtest.py`。
4. `tests/test_core.py`：看「截断一致性」测试怎样保证没有未来函数。
5. 界面：`web/index.html` 看结构，`web/app.js` 搜 `async function load` 看各页面加载。

应用内「使用指南 → 源码」可以直接打开上面每个文件（只读、带行号）。源码清单的覆盖范围：`run.py`、`requirements.txt`、`start-windows.bat`、`quantlab/` 下全部 `.py`、`quantlab/web/` 下的 html/js/css/svg（不含 `vendor/`）、`packaging/` 下的 `.py` 和 `.nsi`、`tests/` 下的 `.py`。排除：第三方库、`build/`、`dist/`、`__pycache__/`。

## 7. 修改与重建

**从源码运行**（需要 Python 3.10+）：

```bash
cd quant-lab
pip install -r requirements.txt
python run.py              # 窗口模式
python run.py --browser    # 浏览器模式
```

Windows 也可以双击 `start-windows.bat`（第一次会自动建虚拟环境）。

**跑测试**：

```bash
python -m unittest discover -s tests -v
node --check quantlab/web/app.js
```

**打包**（在目标平台上执行）：

```bash
pip install -r requirements.txt pyinstaller pillow
python packaging/build.py
```

- Windows：`dist/QuantLab-Setup-<版本>-x64.exe`（需要 NSIS）和 `dist/QuantLab-<版本>-windows-x64.zip`。
- macOS：`dist/QuantLab.app` 和 `dist/QuantLab-<版本>-macos-arm64.dmg`。LightGBM 需要 OpenMP：先 `brew install libomp`。
- `build.py` 会把 `README.md`、`docs/` 全部内容复制到包内 `projectdocs/`，把手写源码打成 `projectsrc/QuantLab-source.zip`，应用内「使用指南」读的就是它们。

**CI**：推送到 `claude/**` 分支且改动了 `quant-lab/` 时，`.github/workflows/quant-lab.yml` 在 Ubuntu/Windows 上跑测试，在 Windows 和 macOS（Apple Silicon，`macos-latest`）上分别打包、自检和冒烟测试（启动 → 接口可用 → 发退出指令 → 确认进程结束、端口释放），产物在 Actions 页面下载。打 `quant-v<版本>` 标签时发布到 Release。

**改版本号**：`quantlab/__init__.py` 的 `__version__`；同时更新 `docs/` 里写到版本的地方。

**扩展**：加因子、加模型的方法见 [使用说明](<使用说明.md>) 第 6 节。
