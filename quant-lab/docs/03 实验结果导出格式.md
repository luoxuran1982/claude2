本篇说明 1.2.0 新增的「导出实验结果 JSON」的文件格式。它是给其他程序读的，首先是新项目「Qlib 量化研究台」：把 QuantLab 的一次实验和 Qlib 的实验放在同一数据、同一区间上并排比较。返回 [00 项目阅读入口](<00 项目阅读入口.md>)。

## 怎么导出

| 方式 | 操作 |
| --- | --- |
| 界面 | 「📈 实验结果」→ 选一个实验 → 右上角「导出实验结果 JSON」。窗口模式弹出「另存为」，浏览器模式直接下载，默认文件名 `<实验名称>-实验结果.json` |
| 命令行 | `python run.py export <实验编号> result.json`（安装版：`QuantLab.exe export <实验编号> result.json`） |
| 本机接口 | `GET http://127.0.0.1:<端口>/api/export?id=<实验编号>&kind=result`（端口每次启动随机，只能本机访问） |
| 程序里 | `from quantlab import export; doc = export.build(runs, store, run_id)`；`export.validate(doc)` 检查结构 |

文件是 UTF-8 编码的标准 JSON（不含 `NaN`/`Infinity`，缺失值一律写 `null`），一般几百 KB 到几 MB。

## 版本与兼容

- `format` 固定为 `"quantlab.experiment-result"`，读的一方先检查它。
- `format_version` 当前为 `"1.0"`。只**增加**字段时不改主版本号（读的一方忽略不认识的字段即可）；改名、删除或改含义时主版本号加 1（`"2.0"`），并在本篇写明。
- `app.version` 是导出时的 QuantLab 版本，`run.app_version` 是跑这次实验时的版本（老实验可能是 1.1.0）。

## 顶层结构

```json
{
  "format": "quantlab.experiment-result",
  "format_version": "1.0",
  "exported_at": "2026-10-14T15:20:00+0800",
  "app": {"name": "QuantLab 量化学习实验室", "version": "1.2.0"},
  "run": {...}, "dataset": {...}, "config": {...}, "periods": {...},
  "universe": {...}, "model": {...},
  "daily_returns": {...}, "nav": {...}, "ic": {...},
  "metrics": {...}, "assumptions": {...}
}
```

## 字段说明

### run：这次实验

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 字符串 | 实验编号，如 `r20261014_093012_123`（也是数据目录 `runs/` 下的文件夹名） |
| `name` | 字符串 | 实验名称 |
| `created` | 字符串 | 运行完成时间 `YYYY-MM-DD HH:MM:SS`（本机时间） |
| `app_version` | 字符串 | 跑这次实验的 QuantLab 版本 |
| `elapsed_seconds` | 数 | 用时（秒） |

### dataset：用的数据

| 字段 | 说明 |
| --- | --- |
| `id`、`title` | 数据集编号和名称 |
| `demo` | `true` = 模拟演示数据，**不是真实行情**，对比时要排除 |
| `start`、`end` | 数据集的日期范围 |
| `updated` | 数据集最后写入时间 |
| `sources` | 股票池里各数据来源的股票数，如 `{"通达信": 4800, "AKShare": 120}`；来源取值：`通达信`、`本地文件`、`AKShare`、`富途 OpenD`、`演示数据` |
| `adjust` | 股票池用到的复权口径，如 `["复权因子列"]`、`["跳空估算"]`、`["前复权"]` |
| `missing` | 只有数据集已被删除时出现，值为 `true`；这时上面几项缺失，其余字段不受影响 |

### config：完整实验配置

和界面「新建实验 → 复制配置 JSON」以及实验文件夹里的 `config.json` 完全相同，可以原样粘贴回 QuantLab 重跑。主要分组：`universe`（股票池规则）、`period`（数据区间）、`features`（因子，`resolved` 是实际用到的因子名列表）、`label`（预测目标）、`model`、`walk`（滚动训练）、`backtest`（回测参数和费用）。各参数含义见 [使用说明](<使用说明.md>)。

### periods：区间

| 字段 | 说明 |
| --- | --- |
| `data.start` / `data.end` | 配置里的数据区间；留空时取数据集范围 |
| `train.start` / `train.end` | 第一段训练的开始日 ～ 最后一段训练的结束日（决策日） |
| `test.start` / `test.end` / `test.days` | 样本外回测区间和交易日数，等于 `daily_returns` 覆盖的范围 |
| `folds` | 每一段滚动训练：`fold`（序号）、`train_start`、`train_end`、`test_start`、`test_end`、`n_train`、`n_valid`、`n_test`（样本数）、`skipped`（训练样本不足被跳过时的原因，否则为 `null`） |

滚动训练里训练段和测试段之间留了「预测周期 + 1」个交易日的隔离带，所以 `train_end` 早于下一段 `test_start`。

### universe：股票池

| 字段 | 说明 |
| --- | --- |
| `rules` | 股票池规则（板块、上市天数、成交额门槛、是否排除 ST） |
| `symbols` | 进入股票池的全部代码，统一格式 `sh600000` / `sz000001` / `bj830799`（小写市场前缀 + 6 位数字） |
| `n_symbols` | 股票数 |
| `benchmark` | 基准：指数代码（如 `sh000300`）或 `股票池等权` |

股票池是**动态**的：每个调仓日只在满足规则（上市满 N 天、流动性够、非 ST、可交易）的子集里选股；`symbols` 是整段时间里出现过的全部股票。1.2.0 之前跑的实验没有记录这个列表，导出时用「有样本外预测的股票」代替。

转换成 Qlib 代码：`sh600000` → `SH600000`（大写即可）。

### daily_returns：日收益序列（对比的核心）

```json
"daily_returns": {
  "dates": ["2019-01-03", "2019-01-04", ...],
  "strategy": [0.0021, -0.0134, ...],
  "benchmark": [0.0015, -0.0098, ...]
}
```

- 三个数组等长，按日期升序；日期是 A 股交易日 `YYYY-MM-DD`。
- `strategy[i]` = 第 i 天收盘净值 / 前一天收盘净值 − 1，**已扣除**佣金（含最低 5 元）、印花税、滑点；用小数表示（0.01 = 1%）。
- `benchmark[i]` 同口径的基准日收益（指数收盘或股票池等权）。
- 回测第一天没有前一天，所以 `dates` 比 `nav.dates` 少第一天。
- 把 `(1 + strategy)` 连乘就得到净值；QuantLab 的年化、夏普、最大回撤都由它算出（一年按 244 个交易日）。

### nav：净值（归一到 1）

`dates`、`strategy`、`benchmark` 三个等长数组，第一天都是 1.0。和 `daily_returns` 是同一份数据，方便直接画图。

### ic：IC / RankIC 序列

| 字段 | 说明 |
| --- | --- |
| `dates` | 每个调仓日（决策日） |
| `ic` | 当天模型得分与未来 `horizon` 日收益的截面皮尔逊相关 |
| `rank_ic` | 同上，但用排名（斯皮尔曼） |
| `horizon` | 预测周期（交易日） |
| `step` | 调仓间隔（交易日）；IC 每 `step` 天一个点 |

数组里个别位置可能是 `null`（当天有效股票太少，算不出相关）。未来收益默认是「t+1 日开盘买入 → t+1+horizon 日开盘卖出」（配置 `label.price` = `open`），和回测的成交时点一致；改成 `close` 时是收盘到收盘。

### metrics：主要指标

| 字段 | 含义 | 单位 |
| --- | --- | --- |
| `annual_return` | 年化收益（复利） | 小数 |
| `total_return` | 区间总收益 | 小数 |
| `annual_volatility` | 年化波动率 | 小数 |
| `sharpe` | 夏普比率（无风险利率按 0） | — |
| `sortino` | 索提诺比率 | — |
| `max_drawdown` | 最大回撤（负数，如 -0.25） | 小数 |
| `calmar` | 年化收益 / 最大回撤绝对值 | — |
| `win_rate_daily` | 日胜率（日收益 > 0 的比例） | 小数 |
| `benchmark_annual_return` / `benchmark_max_drawdown` | 基准的年化收益和最大回撤 | 小数 |
| `excess_annual_return` | 年化收益 − 基准年化收益 | 小数 |
| `information_ratio` / `tracking_error` | 信息比率 / 年化跟踪误差 | — / 小数 |
| `beta` / `alpha` | 相对基准的 Beta、年化 Alpha | — / 小数 |
| `ic_mean` / `icir` | IC 均值 / IC 均值除以标准差 | — |
| `rank_ic_mean` / `rank_icir` / `rank_ic_positive_ratio` | RankIC 均值 / RankICIR / RankIC 为正的比例 | — |
| `turnover_annual` | 年换手（年成交额 / 平均资产 / 2） | 倍 |
| `fees_ratio_annual` | 年手续费占平均资产比例 | 小数 |
| `n_trades` / `trade_win_rate` | 成交笔数 / 平仓盈利的比例 | 笔 / 小数 |

算不出来的指标写 `null`（例如没有交易时的交易胜率）。

### model 与 assumptions

- `model`：模型类型列表（如 `["lgbm"]`、`["lgbm", "ridge", "mlp"]` 表示集成）、`horizon`、`n_features`、`features`（因子名）、`label`、`walk`，是 `config` 里相关部分的摘录。
- `assumptions`：文字说明回测假设：一年 244 个交易日、日收益口径、A 股规则（T+1、涨停买不进/跌停卖不出、停牌不交易、一手 100 股）、IC 的算法。

## 对比时要注意

1. **同数据**：`dataset.sources` 和 `dataset.adjust` 要和对方一致；`demo: true` 的不要拿来比。
2. **同区间**：用 `periods.test` 截取对方的收益序列；只比较两边都有的交易日。
3. **同股票池**：`universe.symbols` 是出现过的全部股票，每天实际可选的更少（见上文「动态股票池」）。
4. **同成本**：QuantLab 的收益已扣费用；对方若是不含费用的收益，差距里有一部分是成本。
5. **IC 口径**：QuantLab 的 IC 只在调仓日计算（每 `step` 天一个点），标签是开盘到开盘；Qlib 默认每天计算、常用收盘到收盘，数值会有差别。

## 示例：用 Python 读

```python
import json
import pandas as pd

doc = json.load(open("实验结果.json", encoding="utf-8"))
assert doc["format"] == "quantlab.experiment-result" and doc["format_version"].startswith("1.")
r = pd.DataFrame({"strategy": doc["daily_returns"]["strategy"],
                  "benchmark": doc["daily_returns"]["benchmark"]},
                 index=pd.to_datetime(doc["daily_returns"]["dates"]))
nav = (1 + r).cumprod()
ic = pd.DataFrame({"ic": doc["ic"]["ic"], "rank_ic": doc["ic"]["rank_ic"]}, index=pd.to_datetime(doc["ic"]["dates"]))
print(doc["metrics"]["annual_return"], doc["metrics"]["sharpe"], doc["metrics"]["max_drawdown"])
```

字段的生成代码在 `quantlab/export.py`（`build()`），结构检查在同一文件的 `validate()`，测试在 `tests/test_export.py`。
