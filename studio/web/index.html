        怎么用
        
    
          
      
        1. 创作：填主题、受众、时长，写 3–5 句你自己的观点，粘贴参考资料。点“生成”——默认只调用一次模型，拿到标题、分镜、封面标题、简介、事实清单。超过 6 分钟的视频分“大纲 + 每章一次”。
          2. 
      
        2. 分镜：逐镜改口播和画面。画面是程序按模板画的（标题卡、要点、关键词、数字、代码、流程、图表、对比、表格、引语、配图），不调用生图模型，文字和公式不会画错。
          3. 
      
        3. 审片：看风险提示、核对低把握度的事实、检查读音、点掉配错的图。勾选“发布时声明 AI 内容”。
          4. 
      
        4. 导出：横版完整版给 YouTube 和 B站，竖版精简版给抖音、视频号和 Shorts。每次导出都附带 SRT 字幕、口播稿、两张封面和“发布信息.txt”。
          5. 
      
        5. 发布：手动发布。不要用脚本或群控批量发；每个平台每个题材一个号。
          6. 
    
        
    
        为什么这样省 token
        
    
          
      
        • 模型只写文字；配音、画面、字幕时间轴、合成全在本机完成，渲染多少次都不再花钱。
          • 
      
        • 系统提示词固定放在最前面，DeepSeek 等服务商的前缀缓存按缓存价计费。
          • 
      
        • 相同请求命中本地缓存；改一句口播只重配那一句（配音也有缓存）。
          • 
      
        • 批量生成可放在服务商的低价时段跑。
          • 
    
        
    
        为什么配图不容易配错
        
    
          
      
        • 只有“具体事物”镜头才配图；抽象概念、数据、人名一律用文字卡、图表。
          • 
      
        • 模型为配图镜头写英文画面描述，和素材库标签比对打分；低于及格线就不用图。
          • 
      
        • 同一视频、最近 30 个项目里用过的图不重复；审片时确认过的图会加分。
          • 
    
        
    
        导入分镜 JSON 的格式
        
    
        {"title": "...", "cover_titles": ["..."], "description": "...", "tags": ["..."],
 "scenes": [{"type": "title|bullets|keyword|stat|code|flow|chart|compare|table|quote|image",
             "category": "concrete|abstract|data|entity", "heading": "...", "narration": "口播",
             "data": {...}, "image_query": "english description", "short": false}],
 "claims": [{"text": "...", "confidence": "high|medium|low"}]}
        
    
        合规提示只是规则匹配，不是法律意见。投资内容上线前建议请律师过一遍边界。
