## 3. 阅读路线

**外壳**（约 1 小时）：

1. `run.py` → `hotradar/app.py` 的 `main()`：知道启动做了什么、退出怎么收尾。
2. `hotradar/server.py`：浏览 `do_GET` / `do_POST`，知道网页能调哪些接口。
3. `hotradar/runner.py` 的 `start()` 和 `_watch()`：一次抓取怎么起、进度怎么来。
4. `hotradar/worker.py`：工作进程里对上游做了哪些运行时替换。
5. `hotradar/configio.py`：配置怎么写回上游格式。
6. `hotradar/web/app.js`：从 `renderStatus()` 开始看界面怎么跟着状态变。

**上游**（约 2 小时）：

1. `upstream/trendradar/__main__.py`：`main()` → `NewsAnalyzer.run()` → `_crawl_data` / `_crawl_rss_data` / `_execute_mode_strategy` / `_run_analysis_pipeline` / `_send_notification_if_needed`。
2. `upstream/trendradar/core/loader.py`：每个配置项和对应的环境变量。
3. `upstream/trendradar/crawler/fetcher.py`：newsnow 请求、重试、域名校验。
4. `upstream/trendradar/core/frequency.py` + `core/analyzer.py`：关键词语法和排序权重。
5. `upstream/trendradar/storage/local.py` + `sqlite_mixin.py` + `schema.sql`：数据怎么存、新增怎么判断。
6. `upstream/trendradar/report/html.py`：报告页面（3000 多行，主要是 HTML/CSS/JS 模板）。
7. `upstream/trendradar/notification/`：分批和各渠道格式。
8. `upstream/trendradar/ai/`：AI 分析、筛选、翻译；提示词在 `config/*.txt`。
9. `upstream/mcp_server/server.py`：MCP 工具清单。

## 4. 从源码运行

需要 Python 3.12（上游要求）。

```bash
cd hot-radar
python -m venv .venv && source .venv/bin/activate        # Windows：.venv\Scripts\activate
pip install -r requirements.txt -c constraints.txt
python run.py                 # 应用窗口
python run.py --browser       # 用浏览器
python run.py --serve-only --port 18790   # 只起服务，地址（带令牌）打印在终端
HOTRADAR_DATA=/tmp/hr python run.py       # 用临时数据目录，不碰正式数据
```

`constraints.txt` 由上游 `uv.lock` 导出，保证 LiteLLM、FastMCP、pydantic 等与上游测过的版本一致（不加约束时新版 pydantic 会让 MCP 导入失败）。

## 5. 测试

```bash
python -m unittest discover -s tests -v          # 外壳：单元 + 集成（真跑离线演示、MCP 看门狗），全部离线
cd upstream && python -m pytest -q tests && cd ..  # 上游自带测试（需 pip install pytest）
node tests/web.test.js                            # 缩放档位、Markdown
python packaging/smoke.py --source                # 源码冒烟：启动 → 接口 → 演示 → MCP → 退出
python packaging/smoke.py --source --live         # 另外真实访问 newsnow 抓一次（需要网络）
```

## 6. 打包

```bash
pip install -r requirements.txt -c constraints.txt pyinstaller pillow
python packaging/build.py
```

在哪个系统上运行就打出哪个系统的包：macOS 出 `dist/热点雷达.app` 和 `dist/HotRadar-<版本>-macOS-arm64.dmg`；Windows 出 `dist/HotRadar/`、`dist/HotRadar-<版本>-windows-x64.zip`，装了 NSIS（`choco install nsis`）时再出 `dist/HotRadar-Setup-<版本>-x64.exe`。

`build.py` 的要点：

- `stage_project()` 把使用指南清单里的全部文件复制到 `build/project/`，整体打进包里（网页、上游默认配置、样例、文档、源码都从这里读）。
- PyInstaller 参数：`--paths upstream` 让分析器找到 `trendradar` / `mcp_server`；`--collect-submodules` 收齐上游模块；`--collect-all litellm fastmcp mcp`（LiteLLM 有大量数据文件和动态导入）；`tiktoken_ext` 插件；上游的 `storage/*.sql` 按模块相对路径放；排除 boto3（桌面版不用远程存储）。
- macOS 改 `Info.plist` 后用临时签名（`codesign --sign -`）；没有 Apple 开发者证书，首次打开要右键 → 打开。

CI（`.github/workflows/hot-radar.yml`）：Ubuntu 上跑全部测试和源码冒烟，并单独尝试一次真实抓取（失败不阻塞）；macOS（Apple 芯片）和 Windows 上打包并对安装包做冒烟测试，Windows 再检查 WebView2 窗口能否创建；产物 `HotRadar-macOS-arm64`、`HotRadar-windows-x64`、`HotRadar-source`。

## 7. 常见修改怎么做

| 想做的事 | 改哪里 |
| --- | --- |
| 界面上多一个可改的 `config.yaml` 字段 | `configio.FIELDS` 加一行（类型和范围）；`index.html` 对应分类里加一个带 `data-k="路径"` 的控件（复选框/数字框/输入框/下拉框会被 `applyConfig()`、`collect()` 自动处理）；下拉框的中文名加到 `app.js` 的 `ENUM_LABELS` |
| 多一种密钥 | `configio.SECRETS` 和 `SECRET_YAML` 各加一行（键 → 上游环境变量名）；`app.js` 的 `CHANNELS` 里引用 |
| 多一个接口 | `server.py` 的 `do_GET` / `do_POST`；写操作一定放在 `do_POST`（自动校验令牌） |
| 进度识别不准 | `runner.Progress` 的正则对照上游的 `print` 语句 |
| 改了程序 | 同一次提交里改 `hotradar/__init__.py` 的版本号、`docs/`、README，CI 重新出两个平台的安装包 |

## 8. 升级上游 TrendRadar

1. 在临时目录 `git clone https://github.com/sansan0/TrendRadar`，切到新版本。
2. 用 `git archive HEAD | tar -x -C hot-radar/upstream-new` 导出，按 UPSTREAM.md「复制时没有带过来的文件」删掉同样的文件。
3. `grep -rn "热点雷达补丁" hot-radar/upstream/` 列出 6 处补丁，在新版本对应位置重新改（行号可能变）。
4. 替换 `hot-radar/upstream/`；`cd upstream && uv export --frozen --no-dev --no-hashes --format requirements-txt --no-emit-project` 重新生成 `constraints.txt` 的版本列表；`requirements.txt` 的直接依赖版本对照新的 `pyproject.toml`。
5. 检查上游的输出文字有没有变（`runner.Progress` 靠它们算进度）、配置字段有没有改名（`configio.FIELDS`）、`worker.py` 替换的函数还在不在。
6. 跑第 5 节全部测试；更新 `hotradar/__init__.py` 的 `UPSTREAM_VERSION` / `UPSTREAM_COMMIT`、UPSTREAM.md、本文档，递增热点雷达版本号。

用户数据目录里的 `config.yaml` 不会被新版本覆盖（保留用户修改）；如果上游新增了配置项，上游的加载器对缺失项有默认值，界面上新字段显示默认值。AI 提示词随版本更新（旧文件备份成 `.bak`）。
