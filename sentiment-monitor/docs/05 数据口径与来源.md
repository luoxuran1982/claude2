> 本篇列出 v0.3 每一类数据从哪来、什么口径、多久更新、许可和限制。核对日期：2026-10-21（在用户 Mac 上实测）。v0.2 原有来源的说明见 [README](<../README.md>) 的「消息来源」。

## 1. 来源总表

| 类型（`sources` 表的 `type`） | 数据从哪来 | 是不是官方接口 | 时间口径 | 默认间隔 |
|---|---|---|---|---|
| `rsshub` RSSHub 路由 | 本机运行的 RSSHub（默认 `http://127.0.0.1:1200`），它现场抓取目标网站 | 否：RSSHub 社区写的抓取脚本，网站改版会失效 | RSS 里的 `pubDate`；没有时用抓到的时间 | 金融类 10 分钟，其他 30 分钟 |
| `newsnow` 热榜 | 开源项目 newsnow 的公开实例 `newsnow.busiyi.world`（热点雷达用的同一个） | 否：第三方聚合，可能限流或停服 | 热榜条目多数**没有发布时间**，记为**抓到的时间**；摘要写「热榜第 N 名」 | 10–15 分钟 |
| `cninfo` 巨潮资讯公告 | `www.cninfo.com.cn/new/hisAnnouncement/query`（网站自用接口） | 否（巨潮是证监会指定信披网站，但这个接口不是开放 API） | `announcementTime`，巨潮给的是**公告日期的 0 点**，不是精确发布时刻；晚于当前时间的按当前时间入库 | 10 分钟 |
| `hkex_news` 港交所披露易 | `www1.hkexnews.hk/ncms/json/eds/lci…_1.json`（网站自用 JSON） | 否 | `relTime`，香港时间（= 北京时间），精确到分钟 | 10 分钟 |
| `cninfo_stock` 巨潮·按监控对象（v0.3.1） | 先取巨潮的代码对照表 `new/data/szse_stock.json`、`bj_stock.json`、`hke_stock.json`（股票代码 → 巨潮内部编号 orgId，每天取一次），再按 `stock=代码,orgId` 查该公司最近公告 | 否（网站自用接口） | 同 `cninfo`：公告日期 0 点 | 30 分钟 |
| `sec_filings` SEC·按监控对象（v0.3.1） | SEC 官方接口：`www.sec.gov/files/company_tickers.json`（代码 → CIK，每天取一次）+ `data.sec.gov/submissions/CIK….json`（该公司全部申报） | **是**（SEC 公开的数据接口，要求 UA 带联系邮箱、每秒不超过 10 次） | `acceptanceDateTime`（SEC 接收时刻，UTC，精确到秒） | 60 分钟 |

## 1.1 按监控对象查公告和「全市场公告 + 只存命中」的区别（v0.3.1）

| | 全市场公告（`cninfo`、EDGAR 实时流） | 按监控对象（`cninfo_stock`、`sec_filings`） |
|---|---|---|
| 怎么对应到公司 | 靠标题里出现的公司名、别名、代码去匹配 | 直接用股票代码查，**不会漏也不会错配** |
| 会漏吗 | 会：每次只拿最新 50 条（巨潮）或 40 条（EDGAR），两次抓取之间超过这个数就漏 | 不会：每次拿该公司最近 20 条 / 90 天 |
| 适合 | 没有代码的主题词、想看全市场动态 | 有代码的股票 |

## 2. 订阅目录的两部分

- **RSSHub 全部路由**：应用运行时请求本机 RSSHub 的 `/api/namespace`，拿到全部网站和路由（2026-10-21 本机版本：**2066 个网站、4008 条路由**），缓存 6 小时。分类用 RSSHub 自己的 `categories` 字段，只把名称译成中文（例如 `finance` → 金融财经）。RSSHub 没运行时，用上一次成功读到的目录；从没读到过时，只显示直连源。
- **直连源（90 个）**：清单写在 `monitor/catalog.py` 的 `DIRECT`，按性质放进同样的 RSSHub 分类：交易所、监管、央行、海外财经媒体和财经热榜放「金融财经」，社交热榜放「社交媒体」等。

## 3. 每条目录项上的标记是什么意思

| 标记 | 含义 | 依据 |
|---|---|---|
| 直连 | 不经过 RSSHub，本应用直接请求 | `DIRECT` 清单 |
| 实测 N 条 · 日期 | 开发时在用户 Mac 上批量请求过一次，当时拿到 N 条 | `monitor/catalog_tested.json`；只代表那一天能用 |
| 本机测试 N 条 / 本机测试失败 | 你在应用里点过「测试」的最近一次结果 | 数据库 `kv` 表的 `catalog_health` |
| 需 Cookie/配置 | RSSHub 要求填登录 Cookie 或 API Key 才能用 | RSSHub 路由的 `features.requireConfig` |
| 需内置浏览器 | RSSHub 要启动 Puppeteer 无头浏览器才能抓 | `features.requirePuppeteer` |
| 有反爬 | 目标网站有反爬措施，可能时好时坏 | `features.antiCrawler` |
| 需填参数 | 路由里有必填参数（如用户 ID），要先填才能订阅 | 路由路径里不带 `?` 的 `:参数` |

**不绕过登录和反爬**：需要 Cookie 的源（小红书、抖音用户页、微博搜索、雪球个股讨论等）本应用不代填 Cookie、不破解验证。2026-10-21 实测这几类在本机 RSSHub 上返回 503。社交平台的整体热度用 newsnow 热榜代替。

## 4. 只存命中

量大的源（巨潮全市场公告每天数千条、SEC EDGAR 实时申报、热榜、科技媒体）默认勾选「只存命中」：抓回来的条目只有命中某个监控对象（名称、别名、代码）时才入库。原因：不命中的条目对舆情监控没有用，全部入库会让资讯流和数据库迅速膨胀。可以在「数据源 → 编辑」里取消。

财经快讯、监管和央行新闻默认**不**勾选：它们量不大，作为「市场快讯」整体保留有参考价值（受「设置 → 保存未命中的资讯」总开关控制）。

## 5. 缺失、零、失败怎么区分

| 情况 | 界面上 |
|---|---|
| 请求失败（网络、503、改版） | 数据源页红点 + 具体报错；「连续失败 N 次，间隔已放大 X 倍」；资讯不受影响 |
| 成功但没有新条目 | 绿点，「获取 N 条，新增 0 条」 |
| 成功但对方返回 0 条 | 绿点，「获取 0 条」——这是对方的数据为空，不是失败 |
| 热榜没有发布时间 | 用抓到的时间，摘要标「热榜第 N 名」，不伪造发布时间 |
| 巨潮只给日期 | 发布时间显示为当天 0 点（或抓取时刻），不是精确时刻 |

## 6. 失败退避

一个源连续失败时，下次抓取的等待时间变成「间隔 × 2^失败次数」，最多 8 倍（例如 10 分钟间隔，连续失败 3 次后变 80 分钟）。成功一次就恢复原间隔。目的是不去反复敲打不通的网站。

## 7. 许可与使用约束

| 对象 | 许可 / 条款 | 本应用怎么用 |
|---|---|---|
| RSSHub | AGPL-3.0 | 只通过 HTTP 调用，不复制代码，不随应用打包；本机自用 |
| newsnow 公开实例 | 开源项目（MIT），公开实例由第三方运营，无服务承诺 | 只调用接口，低频 |
| 巨潮资讯、港交所披露易 | 网站使用条款；数据为公开披露信息 | 只取标题、时间、链接，原文链接回官网 |
| SEC、美联储等官方 RSS | 美国政府公开信息；SEC 要求合理访问频率 | 间隔 ≥ 10 分钟 |
| 媒体 RSS（Bloomberg、FT、CNBC…） | 各媒体条款，一般允许个人通过 RSS 阅读标题和摘要 | 只存标题、摘要和链接，供个人非商业使用 |
