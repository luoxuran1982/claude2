本篇说明有哪些手写源码、先读哪些、关键函数做什么，以及改完之后怎么测试和重新打包。架构总图见 [02 软件框架与系统架构](<02 软件框架与系统架构.md>)。

## 1. 覆盖范围

- **包括**：`sentiment-monitor/` 下全部手写文件：`run.py`、`monitor/**/*.py`、`monitor/web/` 的 HTML/JS/CSS、`packaging/build.py`、`tests/`、启动脚本、`requirements.txt`，以及 `docs/` 和 `README.md`。
- **不包括**：Python 标准库和 psutil 等第三方库、PyInstaller 生成的 `build/` `dist/`、`__pycache__`、运行数据（数据库、日志、浏览器配置）。本项目没有 vendor 进来的第三方前端库，Markdown 渲染器 `markdown.js` 也是手写的。
- **在应用里看**：「使用指南」→「全部手写源码」，列出每个文件的职责和行数，点开带行号只读显示；「下载全部源码（zip）」打包全部手写源码和文档。后端只按白名单返回这些文件，其他路径一律 404。
- **在仓库里看**：[sentiment-monitor/](<../>) 目录。

## 2. 阅读路线

1. [`run.py`](<../run.py>)：从 `main()` 看启动顺序和退出收尾。
2. [`monitor/lifecycle.py`](<../monitor/lifecycle.py>)：`BrowserWindow.open()` 怎样打开应用窗口，`Watchdog.check()` 的退出规则。
3. [`monitor/server.py`](<../monitor/server.py>)：`App._register()` 里的全部接口；`RequestHandler._dispatch()`、`_sse()`。
4. [`monitor/collector.py`](<../monitor/collector.py>)：`_loop()` → `run_source()` → `ingest()`，这是核心流水线。
5. [`monitor/sentiment.py`](<../monitor/sentiment.py>) 的 `analyze()`、[`monitor/matcher.py`](<../monitor/matcher.py>) 的 `Matcher.match()`。
6. [`monitor/db.py`](<../monitor/db.py>)：表结构在文件开头，`add_article()`、`overview()`、`trend()`。
7. [`monitor/sources/`](<../monitor/sources/base.py>)：先看 `base.py` 的 `Source`，再看任一具体来源。
8. v0.3 新增：[`monitor/sources/hub.py`](<../monitor/sources/hub.py>) → [`monitor/rsshub.py`](<../monitor/rsshub.py>) → [`monitor/catalog.py`](<../monitor/catalog.py>)；逐函数讲解见 [04 源码精读](<04 源码精读/00 精读总览.md>)。
9. [`monitor/web/app.js`](<../monitor/web/app.js>)：`route()` 和 `PAGES.*` 各页面；`stackedBars()`/`lineChart()` 手写 SVG 图表；`setZoom()` 缩放；`PAGES.guide` 使用指南；`PAGES.status` 运行状态。

## 3. 关键函数

| 文件 | 函数 / 类 | 作用 |
|---|---|---|
| `run.py` | `main()` | 启动服务、采集、窗口、看门狗；`finally` 里关端口和数据库 |
| `run.py` | `existing_instance()` | 端口上已有本程序时只打开窗口，不启动第二个后台 |
| `monitor/lifecycle.py` | `find_browser()`、`BrowserWindow.open()` | 找 Edge/Chrome，用独立配置目录 `--app` 打开 |
| `monitor/lifecycle.py` | `Watchdog.check()` | 窗口进程结束，或页面全部断开 ≥ 宽限秒数 → 返回退出原因 |
| `monitor/server.py` | `App.shutdown()` | 推送 shutdown、停采集、关窗口、停 HTTP 服务 |
| `monitor/server.py` | `RequestHandler._dispatch()` | 校验 Host 和 `X-Monitor` 头后按路由表分发 |
| `monitor/collector.py` | `Collector._loop()`、`run_source()`、`ingest()` | 调度、抓取、打分、匹配、入库、预警、推送 |
| `monitor/sentiment.py` | `analyze()`、`risk_tags()` | 词典法情感打分（含否定词、程度词）和风险标签 |
| `monitor/matcher.py` | `Matcher.match()` | 名称、别名、代码匹配监控对象，排除词过滤 |
| `monitor/db.py` | `Store` | 全部 SQL 都在这里 |
| `monitor/events.py` | `EventBus` | SSE 订阅、发布、连接数统计 |
| `monitor/guide.py` | `list_docs()`、`list_sources()`、`read_source()`、`source_zip()` | 使用指南的白名单读取 |
| `monitor/procinfo.py` | `snapshot()` | 各进程 PID、RSS/工作集 |
| `monitor/sources/hub.py` | `RsshubSource`、`NewsnowSource`、`CninfoSource`、`HkexNewsSource` | v0.3 四种新数据源 |
| `monitor/rsshub.py` | `status()`、`start()`、`catalog()`、`_flatten()` | 本机 RSSHub 的状态、启动、全部路由目录 |
| `monitor/catalog.py` | `DIRECT`、`all_items()`、`search()`、`default_feed()` | 订阅目录：直连清单、筛选排序、免参数路由的订阅地址 |
| `monitor/collector.py` | `_due()`、`_maybe_start_rsshub()` | v0.3：失败退避、自动启动 RSSHub |
| `monitor/web/markdown.js` | `MD.render()` | Markdown → HTML（标题、表格、代码块、列表、链接、图片、YAML 头） |

## 4. 修改与重建

在 `sentiment-monitor/` 目录下：

```bash
python run.py --demo              # 用源码运行，并写入演示数据
python run.py --no-browser        # 只启动后台（服务模式）：自己用浏览器打开页面地址；没有页面连上前不会自动退出，按 Ctrl+C 结束
python -m unittest discover -s tests -v   # 离线测试，不访问外网（v0.3 起含 tests/test_catalog.py）
```

打包（在哪个系统上运行就打哪个系统的包）：

```bash
pip install pyinstaller psutil
python packaging/build.py
```

- Windows 输出 `dist/SentimentMonitor/`（双击 `SentimentMonitor.exe`）。
- macOS 输出 `dist/SentimentMonitor.app`，CI 再用 `hdiutil` 做成 `SentimentMonitor.dmg`。
- 打包脚本会把 `README.md`、`docs/` 打进程序的 `guide/`，把手写源码原文件（不是 .pyc）打进 `source/`，所以安装版的「使用指南」和「源码」页与仓库一致。

推送到 `claude/` 开头的分支后，GitHub Actions 的 `sentiment-monitor` 工作流会在 Windows 和 macOS（Apple Silicon）上跑测试并构建安装包。

改代码时同步改：版本号（`monitor/__init__.py`）、`docs/` 里受影响的说明、`README.md`。新增手写源码文件后，如果不在 `monitor/guide.py` 的 `SOURCE_PATTERNS` 覆盖范围内，要加进去，并在 `SOURCE_ROLES` 写一句职责。
