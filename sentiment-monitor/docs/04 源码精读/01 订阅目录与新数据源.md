## 本篇会遇到的新词

| 词 | 一句话解释 |
|---|---|
| HTTP 请求头（header） | 请求里除了网址之外附带的「名片」和说明，例如 `User-Agent`（我是谁）、`Referer`（我从哪个页面来）、`Content-Type`（我发的数据是什么格式） |
| GET / POST | 两种最常见的请求方式。GET 只「要东西」，参数写在网址里；POST 「交一张表再要东西」，参数放在请求体里 |
| JSON | 一种文本格式的数据，长得像 Python 的字典和列表；网站接口最常用 |
| RSS / Atom | 两种「新文章清单」的标准 XML 格式，一篇文章是一个 `<item>`（或 `<entry>`） |
| 路由（route） | RSSHub 里「一个网址路径对应一个抓取脚本」，例如 `/cls/telegraph` |
| 类（class）与继承 | 类是「模板」；`class RsshubSource(Source)` 表示 RsshubSource 继承 Source 的全部属性，只改自己不同的部分 |
| 缓存（cache） | 把算过/取过的结果先存起来，下次直接用，省时间 |
| 锁（Lock） | 多个线程同时改同一份数据时，用锁让它们排队，一次只让一个改 |
| 子进程（subprocess） | 由本程序启动的另一个独立程序 |
| 数据库迁移（migration） | 软件升级后，把旧版的数据库表结构改成新版需要的样子，不丢数据 |
| 指数退避（exponential backoff） | 失败后等待时间翻倍再试，越失败等越久，避免一直敲打打不开的服务 |

## 1. 这一组模块负责什么

**一句话**：把「去哪抓」从「写死在代码里的 8 种来源」扩展成「4000 多条可浏览、可测试、一键订阅的目录」，订阅之后仍走原来的「抓取 → 打分 → 匹配 → 入库 → 预警」流水线。

**不负责**：不负责抓网页本身的细节（RSSHub 路由由 RSSHub 社区写，本应用只调用）；不负责登录、Cookie、验证码（规则禁止绕过）。

在分层图里的位置：

```text
界面层   app.js：PAGES.catalog（订阅目录）、PAGES.rsshub（RSSHub 原版）、PAGES.sources（按分类分组）
接口层   server.py：/api/catalog*、/api/rsshub/*
业务层   catalog.py（目录：清单、筛选、排序）  rsshub.py（RSSHub：状态、启动、读路由）
         collector.py（调度：失败退避、自动启动 RSSHub、只存命中）
数据源层 sources/hub.py：RsshubSource、NewsnowSource、CninfoSource、HkexNewsSource
网络层   netutil.py：本机不走代理、SEC 联系邮箱、TLS 断开重试
数据层   db.py：sources 表新增 category / catalog_key / fail_count 三列
外部     本机 RSSHub（独立进程）、newsnow、巨潮、港交所、SEC、各官方 RSS
```

## 4. 关键代码逐段讲解

### 4.1 RSSHub 数据源：最短的一个类

`monitor/sources/hub.py` 第 18–34 行：

```python
18  class RsshubSource(Source):
19      type = "rsshub"
20      label = "RSSHub 路由"
21      desc = "调用本机 RSSHub（设置 → RSSHub 地址）。路由形如 /cls/telegraph，可在「订阅目录 → RSSHub 全目录」里查找。"
22      params_spec = [{"key": "path", "label": "路由", "placeholder": "/cls/telegraph"}]
23  
24      def fetch(self, params, entities):
25          from .rss import parse_feed
26  
27          path = (params.get("path") or "").strip()
28          if not path:
29              raise ValueError("没有填写 RSSHub 路由")
30          try:
31              text = netutil.fetch(rsshub.url_for(path), timeout=rsshub.FETCH_TIMEOUT)
32          except netutil.FetchError as e:
33              raise netutil.FetchError(rsshub.explain_error(str(e))) from e
34          return parse_feed(text)
```

- **第 18 行** `class RsshubSource(Source)`：继承基类 `Source`（在 `sources/base.py`）。基类规定了「每种数据源都要有 `type`、`label`、`params_spec` 和一个 `fetch()`」。这就像公司规定「每个部门都要交同样格式的周报」，调度器只认这个格式，不管里面怎么干活。好处：新增来源时调度器一行不用改。
- **第 22 行** `params_spec`：告诉界面「这种数据源要填哪些参数」。界面的「手动添加」表单就是按它自动生成输入框的。
- **第 25 行** 在函数里面 `from .rss import parse_feed`：把导入放在函数内，是为了避免两个模块互相导入时出现「循环导入」（A 导入 B、B 又导入 A，Python 加载到一半会找不到名字）。代价是每次调用多一次字典查找，可以忽略。
- **第 31 行** `netutil.fetch(rsshub.url_for(path), timeout=rsshub.FETCH_TIMEOUT)`：拼出 `http://127.0.0.1:1200/cls/telegraph` 去请求。超时给 45 秒，比普通请求的 15 秒长，因为 RSSHub 收到请求后要**现场**去抓目标网站，本身就慢。
- **第 32–33 行** `raise … from e`：捕获底层错误，换一句人话再抛出去。`from e` 保留了原始错误链，日志里两层都看得到。
- **第 34 行** 复用 v0.1 就有的 `parse_feed()`：RSSHub 返回的就是标准 RSS，所以不用写新解析器。**这正是复用 RSSHub 的价值**：4000 多个网站各有各的格式，RSSHub 帮我们统一成 RSS，我们只需要一个解析器。

### 4.2 热榜：没有发布时间就不伪造

`monitor/sources/hub.py` 第 43–67 行：

```python
43      def fetch(self, params, entities):
44          pid = (params.get("id") or "").strip()
45          if not pid:
46              raise ValueError("没有填写平台 ID")
47          base = (netutil.options.get("newsnow_url") or "https://newsnow.busiyi.world").rstrip("/")
48          data = netutil.fetch_json(f"{base}/api/s?id={netutil.q(pid)}", {"Referer": base + "/"})
49          if data.get("status") not in ("success", "cache"):
50              raise netutil.FetchError(f"newsnow 没有返回数据（status={data.get('status')}），这个平台可能已下线")
51          now = int(time.time())
52          out = []
53          for rank, d in enumerate(data.get("items") or [], 1):
54              title = strip_html(str(d.get("title") or ""))
55              if not title:
56                  continue
57              extra = d.get("extra") or {}
58              hover = extra.get("hover") or extra.get("info") or ""
59              out.append({
60                  "title": title,
61                  "summary": f"热榜第 {rank} 名" + (f" · {strip_html(str(hover))}" if hover else ""),
62                  "url": d.get("url") or d.get("mobileUrl") or "",
63                  "media": f"{pid} 热榜",
64                  # 热榜条目大多没有发布时间：用抓到的时间，不伪造
65                  "published_at": parse_time(extra.get("date") or d.get("pubDate")) if (extra.get("date") or d.get("pubDate")) else now,
66              })
67          return out
```

- **第 48 行** 请求 `newsnow.busiyi.world/api/s?id=weibo`，返回 JSON：`{"status":"success","items":[{"title":…,"url":…},…]}`。`netutil.q(pid)` 是网址编码（把特殊字符转成 `%xx`），防止 ID 里有空格或中文时把网址弄坏。
- **第 49–50 行** newsnow 对已下线的平台返回 `status` 不是 success/cache（例如 2026-10-21 实测快手、36氪人气榜返回空）。这里明确报错，而不是悄悄返回 0 条——**失败和零要区分**（交付要求的数据诚实条款）。
- **第 53 行** `enumerate(…, 1)`：一边遍历一边计数，从 1 开始，正好是热榜名次。
- **第 65 行** 热榜条目大多没有发布时间：有就用，没有就用 `now`（抓到的时刻），并在摘要里写「热榜第 N 名」。这样资讯流里不会出现编造的时间。

`monitor/sources/hub.py` 第 84–113 行：

- **第 85–90 行** 构造表单。这些字段名不是我们定的，是巨潮网站自己的页面发请求时用的：打开巨潮「最新公告」页，在浏览器开发者工具的「网络」面板能看到同样的请求。`column=szse` 加 `plate` 为空表示全部 A 股。
- **第 94 行** `urllib.parse.urlencode(form).encode()`：把字典变成 `pageNum=1&pageSize=50&…` 这样的文本，再变成字节。给 `fetch()` 传了 `data` 参数，urllib 就会自动改用 **POST**。
- **第 93 行** `Content-Type: application/x-www-form-urlencoded`：告诉服务器「我交的是一张网页表单」，服务器才知道怎么读请求体。
- **第 107 行** 标题拼成「贵州茅台：关于回购股份的公告」。原始标题只有「关于回购股份的公告」，不拼公司名的话，匹配器（按名称、别名、代码找监控对象）就认不出是哪家公司——**这一行决定了公告能不能命中监控对象**。
- **第 111 行** 时间口径：巨潮给的 `announcementTime` 是公告**日期的 0 点**（毫秒），不是精确时刻。`parse_time` 认得毫秒，会除以 1000。超过当前时间的会在入库时被截成当前时间（`collector.ingest` 里 `min(published_at, now)`）。

### 4.5 读取 RSSHub 的全部路由：拍平嵌套结构

RSSHub 提供 `/api/namespace` 接口，一次返回约 4MB 的 JSON，结构是「网站 → 路由」两层嵌套：

```json
{"cls": {"name": "财联社", "lang": "zh-CN",
         "routes": {"/telegraph/:category?": {"name": "电报", "categories": ["finance"],
                    "features": {"requireConfig": false, "requirePuppeteer": false, "antiCrawler": false},
                    "parameters": {"category": "分类，见下表"}, "example": "/cls/telegraph"}}}}
```

`monitor/rsshub.py` 第 113–148 行：

```python
113  def _flatten(namespaces: dict) -> list[dict]:
114      """把 RSSHub /api/namespace 的嵌套结构拍平成一条条可订阅的路由。"""
115      out = []
116      for ns, info in namespaces.items():
117          for path, r in (info.get("routes") or {}).items():
118              feats = r.get("features") or {}
119              cats = r.get("categories") or info.get("categories") or ["other"]
120              params = r.get("parameters") or {}
121              segs = [s for s in path.strip("/").split("/") if s]
122              required = [s[1:].split("{")[0] for s in segs if s.startswith(":") and not s.rstrip("}").endswith("?") and "?" not in s]
123              needs = []
124              if feats.get("requireConfig"):
125                  needs.append("config")
126              if feats.get("requirePuppeteer"):
127                  needs.append("browser")
128              if feats.get("antiCrawler"):
129                  needs.append("anti")
130              example = r.get("example") or ""
131              if example and not example.startswith(f"/{ns}/") and example != f"/{ns}":
132                  example = f"/{ns}{example}"
133              out.append({
134                  "key": f"/{ns}{path}",
135                  "ns": ns,
136                  "site": info.get("name") or ns,
137                  "site_url": r.get("url") or info.get("url") or "",
138                  "lang": info.get("lang") or "",
139                  "name": r.get("name") or path,
140                  "path": f"/{ns}{path}",
141                  "example": example,
142                  "params": {k: (v if isinstance(v, str) else (v or {}).get("description", "")) for k, v in params.items()},
143                  "required": required,
144                  "needs": needs,
145                  "categories": [c for c in cats if c],
146                  "desc": (r.get("description") or "")[:600],
147              })
148      return out
```

```python
213      """到没到抓取时间。连续失败的源退避：间隔 × 2^失败次数，最多 × 8，避免反复请求打不开的网站。"""

215      return now - s["last_run"] >= s["interval_min"] * 60 * backoff
```

- `2 ** min(3, fail_count)`：失败 0 次 ×1、1 次 ×2、2 次 ×4、3 次及以上 ×8。`min(8, …)` 再封顶一次。成功一次，`source_status()` 把 `fail_count` 清零，间隔恢复。

```python
283                      "category": it.get("category") or "", "catalog_key": fk,
284                  })
285                  have.add(fk)
286                  added.append(row["id"])
287              for sid in added:
288                  self.collector.run_now(sid)
289              return {"ok": True, "added": len(added)}
```

- **第 269 行** 先把已订阅的全部 `feed_key` 放进一个**集合**（set）。集合判断「在不在里面」平均是常数时间，比在列表里逐个比快得多。
- **第 271 行** `[:500]`：一次最多订阅 500 个，防止误操作一下子加几千个源。
- **第 275–277 行** 已订阅的跳过：同一地址不会重复订阅（测试 `test_subscribe_flow` 验证了）。
- **第 287–288 行** 新订阅的立即抓一次，用户不用等一个间隔才看到结果。

### 4.12 界面：订阅目录页

页面逻辑在 `monitor/web/app.js` 第 697–911 行。最关键的是「目录项 → 数据源」的转换：

`monitor/web/app.js` 第 817–825 行：

```javascript
817  function itemToSource(it, feed) {
```

- 箭头函数、模板字符串 `` `${it.site}·${it.name}` ``：JavaScript 里把变量嵌进字符串的写法，相当于 Python 的 f-string。
- **第 822 行** 默认间隔：直连源用清单里写好的；RSSHub 金融类 10 分钟，其他 30 分钟。
- **第 823 行** 默认「只存命中」：直连源按清单；RSSHub 非金融类一律只存命中（热榜、论坛、媒体量大，不命中的对舆情监控没用）。

「测试本页」用 4 个「工人」并发测试，避免一次对外发几百个请求：

`monitor/web/app.js` 第 847–862 行：

```javascript
847  async function testCatalogPage() {
848    const b = $("#cTestPage");
849    b.disabled = true;
850    const idx = cat$.items.map((it, i) => i).filter((i) => cat$.items[i].feed && !cat$.items[i].subscribed);
851    let done = 0, ok = 0;
852    const worker = async () => {
853      while (idx.length) {
854        const r = await testCatalogItem(idx.shift(), true);
855        done++; if (r && r.ok) ok++;
856        if ($("#cTestPage")) b.textContent = `测试中 ${done}…`;
857      }
858    };
859    await Promise.all([worker(), worker(), worker(), worker()]);
860    b.disabled = false; b.textContent = "测试本页";
861    toast(`本页测试完成：${ok} 个成功，${done - ok} 个失败`);
862  }
```

- `async`/`await`：JavaScript 的异步写法。`await` 等一个网络请求回来，但**不会卡住页面**，等的时候浏览器还能响应点击。
- **第 859 行** `Promise.all([worker(), worker(), worker(), worker()])`：同时启动 4 个工人，它们共用同一个待办列表 `idx`，各自 `idx.shift()` 取下一条，直到取完。这是最简单的「并发池」写法。JavaScript 在浏览器里是单线程的，`shift()` 不会被两个工人同时执行，所以不需要锁。
- 每测完一条，结果用 `POST /api/catalog/health` 存到后台。后台用锁保证 4 个并发写入不会互相覆盖（`server.py` 第 298 行起）。

## 5. 错误处理与边界

| 情况 | 处理 | 位置 |
|---|---|---|
| RSSHub 没运行 | 目录用上次缓存；RSSHub 源报「RSSHub 没有运行…点启动」；开了自动启动时，调度器每 10 分钟最多试启一次 | `rsshub.catalog`、`explain_error`、`_maybe_start_rsshub` |
| RSSHub 返回 503 | 报「目标网站可能需要 Cookie/登录、有反爬…」；该源进入失败退避 | `explain_error`、`_due` |
| newsnow 平台下线 | 报错而不是返回 0 条 | `NewsnowSource.fetch` 第 49 行 |
| 巨潮返回非 JSON | 报「可能改版或限流」 | `CninfoSource.fetch` 第 96–99 行 |
| SEC 未填邮箱 | 明确提示到设置里填 | `_sec_headers` |
| TLS 握手被挂断 | 重试一次 | `netutil.fetch` |
| 用户连点订阅 | `feed_key` 去重 | `/api/catalog/subscribe` |
| v0.2 旧数据库 | 只加列 + 一次性修正默认源 | `_migrate`、`_fix_v02_defaults` |

## 6. 设计取舍

- **为什么调用 RSSHub 而不是把它的抓取脚本翻译成 Python**：4008 条路由由社区持续维护，网站改版时社区会修；自己翻译等于接下几千个随时会坏的爬虫。代价是要多运行一个 Node.js 服务。另外 RSSHub 是 AGPL，按交付要求不把它的代码抄进来，只调用它的公开接口。
- **为什么目录在运行时读，而不是打包一份**：本机 RSSHub 升级后，路由会增删改；运行时读保证目录和实际能用的路由一致。代价：RSSHub 没开时只能看到缓存或直连部分。
- **为什么直连源不全部走 RSSHub**：交易所、央行的官方 RSS 本身就是标准格式，直接请求少一跳、更稳；巨潮、港交所披露易在 RSSHub 里要么需要具体股票代码，要么要内置浏览器，自己写 30 行更可靠。
- **已知不足**：目录搜索是线性扫描，没有拼音搜索；实测记录只代表开发那天；SEC 只做了全市场申报流，没有「按监控对象查申报」（见过程日志的改进建议）。

## 7. 动手练习

1. **给热榜加一个平台**：在 `catalog.py` 的 `DIRECT` 里照着 `_hot("social-media", "微博", "weibo")` 加一行 `_hot("social-media", "豆瓣小组", "douban-group")`。验证：运行 `python -m unittest tests.test_catalog`（`test_direct_entries_valid` 会检查类型和分类合法、没有重复），再到「订阅目录 → 社交媒体」找到它点「测试」。如果 newsnow 没有这个平台，测试会报「这个平台可能已下线」——这正是 4.2 节讲的「失败和零要区分」。
2. **把失败退避的上限从 8 倍改成 4 倍**：只改 `collector.py` 的 `_due`（两处数字）。验证：改 `tests/test_catalog.py` 的 `test_backoff` 里 `last_run: now - 4800` 那一行，算一算新的边界应该是多少秒，让测试重新通过。
3. **让「港交所披露易」默认也保存不命中的公告**：找到 `DIRECT` 里两行 `hkex_news`，把第 7 个参数 `True` 改成 `False`。想一想：每天几百条港股公告全部入库，资讯流会变成什么样？这就是 4.11 节默认「只存命中」的理由。

## 读完你应该懂了什么

- 一个数据源 = 一个继承 `Source` 的类 + 一个 `fetch()`，调度器只认这个统一格式。
- RSSHub 的价值是把几千个网站统一成 RSS；本应用只要一个 RSS 解析器。
- 网站接口的参数（巨潮的表单、港交所的文件名、SEC 的 User-Agent）都来自观察对方网页自己怎么请求、对方文档怎么规定。
- 多线程下读-改-写要加锁，锁的范围尽量小；慢操作放在锁外。
- 数据库升级用「检查列 → 只加缺的列」，同一段代码兼容新老用户。
- 失败退避、并发上限、去重，都是「对别人的服务器礼貌一点」的工程手段。
