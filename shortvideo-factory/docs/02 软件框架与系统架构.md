## 软件要解决什么问题

MoneyPrinterTurbo 本身是一个 Python 项目：用 Streamlit 写的网页界面（WebUI）加一套 FastAPI 接口，平时要装 Python、装依赖、在命令行运行 `webui.sh` / `webui.bat`，再用浏览器打开。AI 短视频工厂做三件事：

1. **变成双击就能用的桌面应用**：自带 Python 运行时、全部依赖和 FFmpeg，在独立窗口里显示，不需要终端、不需要另装任何东西。
2. **按交付要求补齐**：版本号、应用内「使用指南」（完整文档 + 源码只读查看 + 源码 zip）、运行状态（逐进程 PID / 内存）、70%–120% 界面缩放、关窗即停止全部后台、数据放用户数据目录、全中文。
3. **尽量不改上游**：上游只打了 9 处小补丁（见 [UPSTREAM.md](<../UPSTREAM.md>)），以后可以跟着上游升级。1.0.2 起的新功能（知识讲解卡片、1.0.3 的快速通道、防重复提交与取消、日志解读、大模型调用记录、目标时长，1.1.0 的 AI 导演、工坊主题、AI 插图、分镜图、字数控制）放在外壳扩展 `svf_ext/`，上游只在几处入口（P5–P9）调用它；1.1.0 的「审片 / 分镜」「模型调用」两个标签页在外壳主进程里（`svf/review.py`），只读任务文件夹；能在外壳里「包一层」的（大模型调用记录、取消检查、目标时长的提示词）都不改上游源码。

## 两层结构：外壳 + 上游

| 层 | 代码 | 运行在哪 | 职责 |
| --- | --- | --- | --- |
| 外壳（本项目手写） | `svf/`、`packaging/`、`tests/` | 启动器进程（PyInstaller 打包的 ShortVideoFactory 可执行文件） | 窗口、本机服务、反向代理、启停与监视后台、使用指南、运行状态、审片 / 分镜、模型调用（1.1.0）、缩放、中文化、打包 |
| 外壳扩展（本项目手写，1.0.2 起） | `svf_ext/` | 生成界面后台进程（和上游同一个 Python 进程，由 `svf_child.py` 加进 `sys.path`） | 知识讲解卡片（规则切分、1.1.0 的 AI 导演、工坊主题、AI 插图、分镜图和清单；画图、缓动编码）和 1.0.3 的快速通道、混合来源、防重复提交 / 取消 / 已中断、日志解读、大模型调用记录、目标时长、配音/素材失败中文原因、钥匙格式检查、素材下载代理、语言不一致提醒、请启动器打开目录 |
| 上游（MoneyPrinterTurbo） | `upstream/` | 生成界面后台进程（随包 Python 运行 Streamlit） | 文案、关键词、素材、配音、字幕、背景音乐、合成，以及它自己的设置、任务管理界面 |

为什么外壳不直接把 Streamlit 当首页：外壳需要顶栏、使用指南和运行状态，又要能把缩放作用到 Streamlit 页面内部、把 Streamlit 自带的英文提示换成中文。浏览器只允许同源页面互相操作，所以外壳在自己的端口上把 Streamlit **反向代理到 `/app/` 路径下**：窗口里外壳页面和嵌入的 Streamlit 页面同源，外壳在 Streamlit 首页 HTML 里插入一行 `<script src="/ui/inject.js">`，就能做到这些，而上游一行不用改。

## 进程关系

```
ShortVideoFactory（启动器，主进程）
├─ 线程：shell-server（tornado 事件循环：外壳页面、接口、反向代理）
├─ 线程：webui-ready / webui-exit（等后台就绪、发现后台意外退出）
├─ 线程：run-record（后台 PID 变化时更新 run.json）
├─ 子进程（仅 Windows）：msedgewebview2.exe × 若干（WebView2 渲染窗口）
└─ 子进程：生成界面后台 = 随包 python3 svf_child.py → Streamlit（127.0.0.1:随机端口，baseUrlPath=app）
     ├─ 线程：svf-watchdog（每 2 秒检查启动器是否还在）
     ├─ 线程：Streamlit 会话、上游任务线程（一次只跑 1 个生成任务，其余排队）
     ├─ 子进程：ffmpeg（MoviePy / pydub 调用，或知识卡片快速通道的一次合成，生成视频时才有）
     └─ 「打开目录」：经本机 HTTP 请启动器打开（POST /api/open-path，带令牌）→ 启动器调用资源管理器 / 访达
```

macOS 的 WKWebView 网页进程由系统 XPC 服务托管，不是启动器的子进程。

**端口**：启动器的本机服务和 Streamlit 都只监听 `127.0.0.1`，端口都是启动时向系统要的随机空闲端口（命令行 `--port` / `--webui-port` 可指定，测试用）。窗口只访问启动器的端口；Streamlit 的端口只有启动器在用。

**为什么生成界面要单独一个进程**：Streamlit 要求在主线程里运行并接管信号，窗口库（macOS 的 Cocoa）也要求主线程，两者放不进同一个进程；而且上游依赖很重（pandas、pyarrow、MoviePy 等），跑在随包 Python 里能按上游锁定的版本完整安装，避开 Streamlit 被 PyInstaller 打包时丢静态文件和包元数据的老问题。

## 启动和退出的调用链

**启动**（`svf/app.py: Shell.main`）：

1. `setup_logging` → 数据目录 `logs/launcher.log`。
2. `supervisor.cleanup_stale`：读上次的 `run.json`。上次的启动器还活着（PID + 创建时间都对得上）→ 调用它的 `/api/focus` 把窗口调到前面，本次退出；不活着但后台还在 → 结束遗留后台。
3. `clear_quarantine`（仅 macOS 安装版）：去掉随包部件的下载隔离标记。
4. `userdata.prepare`：建 `storage/ fonts/ songs/ logs/`；第一次运行用上游 `config.example.toml` 生成 `config.toml`，界面语言设成中文、默认字幕字体设成随包的思源黑体、默认配音声音设成中文「晓晓」（`zh-CN-XiaoxiaoNeural-Female`）；以后每次启动只检查一件事：配置里还没有 `voice_name` 时补上默认中文声音（1.0.1 起，选过的声音不动）；复制开源字体。
5. `ServerThread.start`：在后台线程起 tornado（`svf/server.py`），绑定 127.0.0.1 随机端口。
6. `WebUI.start`（`svf/supervisor.py`）：用随包 Python 运行 `svf_child.py`，环境变量 `MPT_CONFIG_FILE / MPT_STORAGE_DIR / MPT_FONT_DIR / MPT_SONG_DIR` 指向数据目录。POSIX 上 `start_new_session=True`（自成进程组），Windows 上 `CREATE_NO_WINDOW` 并放进「关闭即结束」的作业对象。`svf_child.py` 启动 Streamlit 前把 `IMAGEIO_FFMPEG_EXE` 指向随包的 imageio-ffmpeg（不受系统 PATH 里其他版本 FFmpeg 影响；你在上游设置里填了 `ffmpeg_path` 时仍以它为准）。启动器另起线程轮询 `/app/_stcore/health`，就绪后状态变成 ready。
7. 写 `run.json`（启动器和后台的 PID、创建时间、端口、令牌）。
8. `run_window`：pywebview 建窗口，载入 `http://127.0.0.1:端口A/`。外壳页面每秒查一次 `/api/status`，后台 ready 后把 iframe 指向 `/app/`。

**退出**（`Shell.shutdown`，正常退出的所有路径都走这里，只执行一次）：

1. `WebUI.stop`：枚举后台进程树（含 FFmpeg）→ POSIX 整个进程组发 SIGTERM / Windows 逐个结束 → 最多等 6 秒 → 仍在的强制结束 → 用 psutil 逐个确认已退出 → 确认 Streamlit 端口不再监听。
2. `ServerThread.stop`：停 tornado、关闭连接、释放端口 A。
3. 删除 `run.json`（运行记录只是收尾，不删任何用户数据）。日志里记一行「已退出：后台进程 […] 已结束，端口 … 已释放」。

触发退出的方式：关闭窗口（`events.closed`）、macOS ⌘Q 等（`webview.start()` 返回）、顶栏「退出」（`/api/quit` → 销毁窗口）、SIGTERM、浏览器模式下页面 3 分钟无访问。

**异常收尾**（启动器崩溃或被强制结束，来不及执行上面的步骤）：

- 后台里的看门狗线程（`svf/child.py: watchdog`）每 2 秒检查父进程：POSIX 看 `getppid()` 是否变了，Windows 用 `OpenProcess + WaitForSingleObject`。启动器不在了 → 整组结束（含 FFmpeg）后自身退出。
- Windows 上作业对象带 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`：启动器进程一结束，系统自动结束作业里的全部进程，不依赖看门狗。
- 下次启动时 `cleanup_stale` 再兜一次底。
- CI 冒烟测试里专门测了这条路径：强制结束启动器后 20 秒内后台和端口都必须消失。

## 上游 MoneyPrinterTurbo 的生成流水线

入口是界面底部「生成视频」→ `app/services/webui_task.py` 把任务交给内存任务管理器（同时只跑 1 个）→ `app/services/task.py: _run_pipeline`：

| 步骤 | 函数 | 做什么 | 外部依赖 |
| --- | --- | --- | --- |
| 1 文案 | `task.generate_script` → `llm.generate_script` | 文案为空时，用固定的英文系统提示词（Role: Video Script Generator）+ 主题、段落数、语言，调用 1 次大模型；失败最多重试 5 次；去掉 Markdown 符号 | 大模型 API |
| 2 关键词 | `task.generate_terms` → `llm.generate_terms` | 让大模型按主题和文案输出 5 个（按文案顺序匹配时 8 个）英文素材搜索词，JSON 数组 | 大模型 API |
| 3 配音 | `task.generate_audio` → `voice.tts` | 默认 Azure TTS V1（即 edge-tts），返回音频和逐词时间（SubMaker）；也支持 Azure V2、硅基流动、MiniMax、ElevenLabs、Gemini 等 | Edge TTS 等 |
| 4 字幕 | `task.generate_subtitle` | 默认 edge：用配音的逐词时间戳按标点切句生成 SRT；可选 whisper：用 faster-whisper 识别配音 | 无 / faster-whisper |
| 5 素材 | `task.get_video_materials` → `material.download_videos` | 逐个关键词调用 Pexels / Pixabay / Coverr 搜索接口（经 `config.proxy`），按比例和分辨率筛选，下载片段直到总时长覆盖配音；有本地缓存。来源是「程序生成」组时改走 `svf_ext.pipeline.prepare_materials`（[补丁 P6]，见下节） | 素材站 API / 本机 |
| 6 拼接 | `video.combine_videos` | MoviePy 把片段裁成目标比例、按单段最大时长切、随机或顺序拼接、可加转场 | FFmpeg |
| 7 合成 | `video.generate_video` | 叠加字幕（PIL 渲染文字，可描边/背景/入场动画）、混入配音和背景音乐（随机挑 `songs/` 里的 mp3）、编码 H.264 MP4 | FFmpeg |

产物写在 `storage/tasks/<任务编号>/`：`script.json`、`audio.mp3`、`subtitle.srt`、`combined-1.mp4`、`final-1.mp4`（程序生成来源另有 `svf-cards.mp4` 和 `knowledge-cards/`）。

## 知识卡片快速通道（1.0.3）与库存视频流程的区别

两条流程的前 4 步（文案、关键词、配音、字幕）完全一样，区别在「画面从哪来、怎样合成」：

| | 库存视频（Pexels / Pixabay / 本地文件等，流程和上游一样） | 知识讲解卡片快速通道（1.0.3） |
| --- | --- | --- |
| 第 5 步 素材 | 按关键词搜索下载几段到几十段实拍片段（尺寸、帧率、编码各不相同） | 按字幕时间分页、选版式（`storyboard.build_pages`），把分页计划交给第 7 步，不编码 |
| 第 6 步 处理片段 | 每段裁成目标比例和分辨率、截到「单个片段最大时长」、按速度变速，各自重新编码 | 没有 |
| 第 6 步 拼接 | FFmpeg 把片段接成 `combined-1.mp4` | 没有 |
| 第 7 步 最终渲染 | MoviePy 在 Python 里逐帧解码 `combined-1.mp4`，把每条字幕画成图层叠上去，混配音和背景音乐，再编码 | 逐帧画讲解页（缓慢缩放/平移、淡入、要点逐条亮起），用 Pillow 把字幕直接画进画面，原始帧经管道交给 **同一条** FFmpeg 命令，命令里同时读配音和背景音乐、混音、编码 |
| 编码次数 | 片段数 + 2 | 1 |
| 编码器 | 上游设置里的 `video_codec`（默认 libx264） | 自动：有可用的硬件编码器就用（先试编 0.2 秒小样），否则 libx264 |
| 字幕字体 | MoviePy `TextClip`（Pillow） | Pillow，同一个字体文件（默认随包思源黑体），不依赖 FFmpeg 的 libass / fontconfig，Windows 上中文不会变方框 |

**为什么 1.0.2 慢**：1.0.2 的卡片走的是左边那列——讲解页先编码成 `svf-cards.mp4`（第 1 次），再「处理片段」（第 2 次）、「拼接」（第 3 次）、MoviePy「最终渲染」（第 4 次）。MoviePy 的最终渲染在 Python 里逐帧做合成（每帧把视频帧解码成数组、把当前字幕图层叠上去、再送去编码），1080×1920 每帧 600 万像素，这一步是瓶颈。

**实测**（容器：Linux、4 核 CPU、无显卡、软件编码 libx264；同一段约 47 秒的文案、假配音、开背景音乐、竖屏 1080×1920；`python tests/cards_task_check.py .. knowledge_cards --long --bgm`，加 `--legacy` 是 1.0.2 流程）：

| 流程 | 全程用时 | 其中 |
| --- | --- | --- |
| 1.0.2（交给上游；`--legacy`） | 235 秒、205.6 秒（两次实测） | 第一次的分步用时：画讲解页并编码 37 秒、处理片段 19 秒、拼接 18 秒、最终渲染 161 秒 |
| 1.0.3 快速通道（每页缓慢缩放/平移，默认） | 33–40 秒（两次实测） | 画帧和编码在同一条流水线里同时进行 |
| 1.0.3 快速通道，`svf_card_motion = false`（静止画面） | 22 秒 | 同一状态的帧不用重新缩放 |

在你的电脑上，用户反馈的 51 秒竖屏视频 1.0.2 最终渲染 5 分钟以上；按上面的比例，快速通道大约是 1 分钟左右，有可用的硬件编码器时更快（编码只是其中一部分，画帧仍在 CPU 上）。实际用时看「日志解读」的「最终渲染」一步。

**同步和比例怎样保证**：画面帧数 = ⌈(配音时长 + 0.6 秒) × 30⌉；字幕按 `subtitle.srt` 的起止时间（上游根据配音的逐词时间生成）决定每一帧画哪条；配音从 0 秒开始，背景音乐循环铺满整条画面、按「背景音乐音量」混音、最后 3 秒淡出（和上游 MoviePy 的做法一致）；画面尺寸取自「视频比例」（9:16 → 1080×1920，16:9 → 1920×1080，1:1 → 1080×1080）。这些在 `tests/test_ext103.py`（音频滤镜、字幕排版）和 `tests/cards_task_check.py --long --bgm`（成片尺寸、时长、有声音）里检查。

调用链（1.0.3）：

```
task._run_pipeline
 ├─ 1–4 照常（文案、关键词[纯卡片跳过]、配音、字幕）
 ├─ 5 get_video_materials ──[补丁 P6]──► svf_ext.pipeline.prepare_materials
 │      └─ build_pages → 记下分页计划（svf-cards.plan.json），返回它；不编码
 └─ 6/7 generate_final_videos ──[补丁 P8]──► svf_ext.pipeline.fast_final_videos
        ├─ parse_srt(subtitle.srt)；按上游规则挑背景音乐（random / 指定文件，音量为 0 不用）
        ├─ fastcards.choose_encoders：上游设置里指定的硬件编码器 → 本平台的硬件编码器（FFmpeg 支持且试编成功）→ libx264
        └─ fastcards.render_final：render.iter_frames 逐帧 → burn 画字幕 → FFmpeg（-i 管道 -i 配音 -stream_loop -1 -i 背景音乐
               -filter_complex volume/afade/amix）→ final-1.mp4；硬件编码中途失败 → 用 libx264 重来一遍
```

例外：选了 Sonilo / ElevenLabs 按画面现做背景音乐时，它们要先拿到合成好的画面，这时仍走 1.0.2 的流程；`config.toml` 的 `[app]` 里 `svf_card_fast = false` 也会退回 1.0.2 的流程。

## 知识讲解卡片（1.0.2，`svf_ext/`）

调用链（第 5 步「素材」被替换，其余步骤原样）：

```
task._run_pipeline
 ├─ 1 文案 generate_script（大模型，或你粘贴的文案）
 ├─ 2 关键词：纯「知识讲解卡片」跳过（[补丁 P6]）；混合来源照常生成
 ├─ 3 配音 generate_audio、4 字幕 generate_subtitle（照常，得到 audio.mp3、subtitle.srt）
 ├─ 5 get_video_materials ──[补丁 P6]──► svf_ext.pipeline.prepare_materials
 │      ├─ 读 script.json（文案）和 subtitle.srt（字幕时间）
 │      ├─ storyboard.build_pages：拆句 → 按字幕对齐每句的时间 → 分页、选版式、要点亮起时间、关键词
 │      ├─ 混合来源：material.download_videos（上游原函数）→ 够用就直接返回素材；不够就 assign_stock 把素材放进普通页
 │      ├─ render.render_video：每页 cards.render_page 画 1.08 倍大图 → 逐帧按 motion_box 裁切缩放（线程池）
 │      │       → 原始 RGB 帧经管道交给 FFmpeg 编码 → svf-cards.mp4；每页另存 knowledge-cards/page-NN.png
 │      └─ 本次任务参数：video_clip_duration = 时间线长度 + 1，video_clip_speed = 1 → 返回 [svf-cards.mp4]
 ├─ 6 combine_videos（照常：一个片段，按所选转场处理开头，对齐配音时长）
 └─ 7 generate_video（照常：烧录字幕、混配音和背景音乐、编码）
```

要点：

- **时间对齐**：上游 edge 字幕是按标点切句、逐句（或逐词）的 SRT。`storyboard.sentence_times` 只比较「会读出来的字」（汉字、字母、数字）：把文案每句的字数累加，对应到字幕的累计字数上，在字幕条目内按字数线性插值，得到每句开口和说完的时间。逐句字幕、逐词字幕都适用；文案和字幕字数不完全一致时按比例缩放。没有字幕时按朗读长度（英文单词约 1.5 个字、数字每位约 0.8 个字）分配配音总时长。换页点放在下一句开口前 0.15 秒。
- **版式规则**全部是本地正则和字符串规则（不调用大模型），见 01 使用指南第 2.4 节的表；规则和画法移植自「AI 知识视频工坊」的 `pipeline.script_to_scenes` 和 `visuals.py`。
- **缓动**：每页先画成比成片大 8% 的图，逐帧用 Pillow 的 `resize(box=小数坐标)` 裁一块缩到成片尺寸，所以缩放和平移是亚像素平滑的；动作在放大 6%、缩小、平移 4.5%（右、上、左、下）之间轮换。换页时把上一页最后一帧和新页前 0.3 秒混合淡入。逐帧计算放在线程池里（Pillow 缩放时释放 GIL），容器里 4 核约 0.75 倍实时。
- **混合**：库存片段解码成同样画幅（FFmpeg `scale…increase,crop`），和卡片帧走同一个编码管道；所以输出仍是一个片段。
- **出错**：任何异常都写进任务失败原因「知识卡片生成失败：…」（中文），完整堆栈在 `webui.log`。

## AI 导演、工坊主题、AI 插图（1.1.0，`svf_ext/director.py`、`studio_cards.py`、`illustrate.py`）

调用链（来源是「知识讲解卡片（AI 导演）」时；「+ AI 插图」多第 5 步）：

```
上游 task.start（写文案 → 配音 → 字幕，和其他来源一样）
└─ task.get_video_materials ─[补丁 P6]─► svf_ext.pipeline.prepare_materials
     1. card_mode(source) → "ai"；_theme("ai") → 默认 studio（工坊深色）
     2. director.direct(文案, 主题, 字幕, 配音时长, W, H, call)
          split_sentences（和规则切分同一个拆句）→ build_prompt（模板 + 变量片段）
          → call = llmlog.step("director") 里调用上游 llm._generate_response（用户配置的大模型；自动进调用记录）
          → extract_json → validate（硬错误重试一次，软毛病修整）→ to_pages（句子 → sentence_times 对字幕 → 每页起止、逐条亮起时间）
          不合格两次 / 调用出错 → storyboard.build_pages（规则切分）
     3. pipeline._director 给每次调用写「程序怎么用」（llmlog.note_use）
     4. （+AI 插图）illustrate.configured() → illustrate.generate → 上游 material.generate_images_openai，路径写进 page.data["image_path"]
     5. shots.save_stills（每页画一张 PNG + 缩略图）→ shots.write_manifest（svf_storyboard.json）
     6. 快速通道计划 → [补丁 P8] fastcards.render_final（逐帧 cards.render_page → studio_cards.render_page）
```

- **为什么在素材这一步才调用导演**：导演只设计画面，页的时间要按配音和字幕对齐，而这时配音和字幕刚生成好；也正好是规则切分原来分页的位置，两种模式出来的都是同一种 `Page` 列表，后面的画图、编码、快速通道完全共用。
- **校验分两级**：会让时间对不上的错误（不是 JSON、没有 pages、句子编号越界 / 不连续 / 重复、没有标题、一半以上版式不认识）算不合格，重试一次（提示词末尾加「上一次的输出没有通过程序校验，原因：……」）；不影响时间的毛病（标题超长、要点超数、缺数据、漏句子）程序修整并记 `warnings`，显示在审片页顶部。调用本身出错（没配大模型、401、网络）不重试，直接退回。
- **画法**：`cards.render_page` 遇到 `theme == "studio"`、版式不在 1.0.x 的 7 种里（table、code、quote、chart、image）、或这一页有插图时，交给 `studio_cards.render_page`；它照搬工坊 `visuals.py` 的版式函数，只把 `scene` 字典换成 `Page`、版面用 `cards.Layout`（避开字幕区）。浅色主题也能画新版式（用 `CODE_COLORS` 补代码配色）。
- **插图**：用上游的文生图函数（同一组 `openai_image_*` 设置），它自带 429/5xx 退避重试、多钥匙轮换、「结果不明（读超时、连接中断）不再提交」的计费保护；这里在它抛出「结果不明 / 已付费但取不到」时停止请求后面的图。

## 审片 / 分镜、模型调用（1.1.0，`svf/review.py`、`svf/web/review.js`、`calls.js`）

```
生成界面后台（svf_ext）写文件                         外壳主进程（启动器）只读
──────────────────────────────                       ─────────────────────────────────────────
knowledge-cards/page-NN.png、thumb-NN.jpg  ─┐         GET /api/tasks           任务列表（主题、来源、有没有分镜和调用）
svf_storyboard.json（分镜清单）             ├─ 任务 ─► GET /api/storyboard?task=  分镜清单 + 成片路径
llm_calls.jsonl（调用记录 + use 行）        │  文件夹  GET /api/llm-calls?task=  调用记录 → annotate：合并 use 行、
script.json、svf_task.json、final-1.mp4    ─┘         GET /taskfiles/<任务>/<文件>   模板/变量着色片段、调用链
                                                      （图片、成片，支持 Range）
```

- 为什么放在外壳：生成页（Streamlit）已经很重，每次交互整页重跑；查看类功能做成外壳的静态页面，只读文件，不影响生成，生成中也能看别的任务。外壳主进程是 PyInstaller 包，只有标准库和 tornado，所以分镜图在后台进程里画好存 PNG，外壳只读图片。
- 生成页和任务管理里的链接（`svf_ext/webui.task_links_html`，P7 的 `render_task_insights` 和 P9 显示）是 `<a class="svf-goto">`，点击由 `inject.js` 调父页面的 `SVFApp.openTask(栏目, 任务)`（同源）。
- **调用链怎么找**：`review.find_links` 把每次更早的、被采用的调用的输出按句切开（至少 6 个字），逐句在后面调用的输入里找，同一来源、中间只隔标点或「[3] 」编号的相邻片段合成一段；最近一次的输出优先。**着色**：`llmlog` 在调用前把提示词里程序填进去的值记成 `prompt_vars`（名字、值、前缀），写记录时切成 `parts`；AI 导演和按字数改写的提示词由外壳自己拼，片段在拼的时候就记下。`review.runs` 把两者叠成一段段 `{文字, 类别, 变量名, 来自第几次调用}`。
- **任务文件接口**：`TaskFileHandler` 继承 tornado 的 `StaticFileHandler`（支持 Range，视频能拖动），只接受 127.0.0.1，只允许图片、mp4、json，路径经 `review.task_file` 检查不能跳出任务文件夹。

## 字数控制方式（1.1.0，`svf_ext/duration.py`、`webui.py`）

`install_duration_hooks` 包住两处：`llm.build_script_prompt`（按档位在提示词末尾加不同的字数要求，同时记下提示词里的变量）和 `llm.generate_script`（「程序检查」档：`count_units` 数字数，`needs_revision` 判断偏差是否超过 ±15%，超过就用 `revise_prompt` 经 `llm._generate_response` 请模型改写一次，改完更接近目标才采用；三档都把 `length_mode / target_chars / first_chars / final_chars / revised` 写进 `svf_task.json` 并打一行「字数控制：……」日志，日志解读认得它）。安装顺序是先 `install_duration_hooks` 再 `llmlog.install`，所以改写算在「写文案」这一步里，「程序怎么用」能写出「请模型改写了一次」。

## 防重复提交、取消、已中断（1.0.3，`svf_ext/tasks.py`）

- **活任务登记表**（进程内）：点「生成视频」通过检查时登记（claimed）；上游 `webui_task.submit_generation` 提交时变成 queued；上游任务线程 `_run_generation` 开始时变成 running，结束时注销。外壳在 `svf_ext.webui` 导入时把这两个函数换成「先登记、再调原函数」的包装（不改上游源码）。
- **按钮置灰**（[补丁 P7]）：登记表里有没被取消的任务 → 按钮文字「生成中…」、`disabled=True`；提交成功后整页重新渲染一次，按钮立即变灰。
- **提交前检查**（[补丁 P7] → `tasks.claim`，加锁）：已有活任务 → 拒绝；同一 Streamlit 会话、参数指纹（`VideoParams` 全部字段的 SHA-1）相同、90 秒内 → 拒绝；登记了 60 秒还没提交的（页面运行被打断）作废。页面脚本 `inject.js` 另外拦下 4 秒内的重复点击。
- **取消**（任务管理 ⏹ → `tasks.cancel`）：① 加入「已取消」集合；② 立即把状态写成失败、`failed_stage="cancelled"`；③ 结束本进程子孙进程里命令行带这个任务 ID 的进程（FFmpeg 的输出文件都在任务目录里）；④ 上游流水线 6 个步骤函数（`generate_script` … `generate_final_videos`）和进度回报函数都包了一层「先检查是否已取消」，发现就抛 `TaskCancelled`，上游按失败收尾；⑤ 状态后端的 `update_task` / `patch_task` 也包了一层：已取消的任务之后的写入一律保持「已取消」，不会被迟到的进度回报写回「生成中」或「完成」。最多等 8 秒让后台线程退出。
- **已中断**（打开任务管理时 [补丁 P7] → `tasks.reconcile`）：本会话「生成中」名单里不在登记表的（连点时没真正提交的）移出名单；状态存储里「生成中」却不在登记表的，写成失败、`failed_stage="interrupted"`。任务目录的 `svf_status.json` 记着 `running` 和进程 PID：程序重启后，历史任务目录里还是 `running` 的也显示「已中断」。「已取消」「已中断」都归到「失败」标签页，可以删除。

## 日志解读与大模型调用记录（1.0.3，`svf_ext/explain.py`、`llmlog.py`）

- **日志解读**：上游每个任务的日志在内存里（`webui_task.get_task_logs`，最近 1000 条），界面每 0.5 秒刷新一次。`explain.explain` 按正则规则把日志行对到 8 个步骤（上游的 `## generating …` 段落标题、`processed clip`、`concatenating`、`still running: elapsed=…`、外壳自己的中文日志），标出每步的状态、开始时间、用时和起始行号；`task failed, … stage: X, error: Y` 对到失败的那一步。行号的算法和界面上的原始日志一致（记录之间用换行连接，一条记录里有换行就占多行），[补丁 P7] 让原始日志显示行号。
- **大模型调用记录**：上游所有大模型调用都经过 `app/services/llm.py` 的 `_generate_response(prompt, app_config)`。外壳把模块里的这个函数换成包装：调用前记下提示词，期间用 `contextvars` 接住 OpenAI SDK `chat.completions.create` 的返回值（拿原始 JSON 和 `usage`），调用后写一行到任务目录的 `llm_calls.jsonl`。「哪一步、哪个任务」由 `llm.generate_script / generate_terms / generate_social_metadata / test_connection` 和 `task.generate_script / generate_terms` 的包装通过 `contextvars` 传下去。写入前 `llmlog.scrub` 去掉配置里所有钥匙、令牌的值和 `sk-…`、`Bearer …` 串。上游把提示词当作一条 user 消息发出（claude_code 适配器另有固定的 system 消息），记录照实写。
- **目标时长**：`llm.build_script_prompt` 的包装在提示词末尾加「Length Requirement」一段（`duration.prompt_addition`），目标取自任务目录的 `svf_task.json`（提交时由 [补丁 P7] 写入）或界面上的当前设置；`task.generate_audio` 的包装在配音完成后记下实际时长、更新实测语速，并写一行「目标时长 … 实际配音 …」日志，日志解读据此显示。

## 「打开目录」为什么 1.0.2 仍然无效（1.0.3）

1.0.2 的修复确实走到了新代码（同一个包里的「知识讲解卡片」来源用户已经用上了，说明 `svf_ext` 在后台里加载成功；按钮 → 上游 `_open_local_path` → `svf_ext.desktop.open_path` → `os.startfile`），而且 `os.startfile` 没报错（报错会在 `webui.log` 里留下「打开目录失败」）。问题在于**发出请求的进程**：

- 生成界面后台是启动器用 `CREATE_NO_WINDOW | CREATE_NEW_PROCESS_GROUP` 启动的后台进程，没有控制台也没有任何窗口，放在「关闭即结束」的作业对象里；按钮回调跑在 Streamlit 的工作线程上，这个线程没有初始化 COM。
- 打开「文件夹」时，Windows 的 ShellExecute 要把请求交给资源管理器（经 COM 委托，由已经在运行的 explorer.exe 开新窗口）；新窗口能不能出现在最前面，取决于发请求的是不是前台进程。从这样一个后台进程、没初始化 COM 的线程发出，请求会静默失败或窗口被压在应用窗口后面——用户看到的就是「没反应」。
- 「播放」好用，是因为打开视频文件是直接启动播放器程序（新进程自己建窗口），不经资源管理器开新窗口。

1.0.3：子进程不再自己打开，改为 `POST /api/open-path`（本机 HTTP，带令牌）请启动器打开。启动器是拥有应用窗口、用户正在操作的前台进程；它在 Windows 上新开一个线程，先 `CoInitializeEx`（单线程套间）、`AllowSetForegroundWindow`，再 `os.startfile`，失败时退回 `explorer.exe <路径>`。接口只接受数据目录之内的路径（解析符号链接后比较），文件则打开它所在的文件夹。打不开时界面显示原因、完整路径和「复制路径」按钮。**上面的原因分析是根据代码和 Windows 的机制推断的，容器里没有 Windows 桌面，不能复现；修好没有要在你的电脑上验收。**

## 中文出错原因、钥匙检查、代理、打开目录（1.0.2）

- **出错原因**：`svf_ext/hints.py` 在后台进程里给 loguru 加了一个接收器，只记 `app.services.voice` 和 `app.services.material` 两个模块的警告和错误（最近 200 条，只在内存里）。配音失败时（[补丁 P6] 任务失败消息、[补丁 P5] 试听失败提示）按最近的日志分类：含 `No audio was received` → 声音和文案语言不一致或代理节点被拒；含 `403` / `Invalid response status` → 服务验证问题，请升级；含连接、超时、DNS、SSL、代理错误 → 网络连不上。素材失败时：Pexels 返回非 JSON / 不支持的响应（401 时就是这样）→ 钥匙无效或 Pexels 暂停发新钥匙；Pixabay `status=400` → 钥匙无效，请复制不要手打；429、Cloudflare、网络错误各有说明。英文原文保留，中文接在后面；界面脚本 `inject.js` 只把英文那句换成中文。
- **钥匙格式**：Pixabay `^\d+-[0-9a-f]{25}$`，Pexels 50–60 位字母数字（实际约 56 位）；可逗号分隔多个，逐个检查；提示里钥匙只显示头尾各 4 位。
- **语言不一致**：只在 Edge / Azure 声音（`azure-tts-v1`、`azure-tts-v2`）时检查。文案（没有文案时用主题）里汉字占字母类字符 30% 以上、或「脚本语言」选了 zh 时算中文；声音名不是 `zh-` 开头就提醒。
- **素材下载代理**：写进上游已有的 `config.proxy`（http、https 同一个地址），并保证它是上游保存配置时用的那份字典，所以会写回 `config.toml` 的 `[proxy]`。上游素材请求每次都现读 `config.proxy`，填了立即生效。
- **打开目录**：1.0.2 是 `svf_ext/desktop.open_path`：Windows `os.startfile(path)`，macOS `open path`，Linux `xdg-open path`；1.0.3 改为经启动器打开（上一节），本进程打开只在没有外壳时兜底。上游原来的「无桌面的 Linux 服务器上改为提示路径」判断保留。

上游还有：FastAPI 接口（`main.py` → `app/asgi.py`，本应用没有启动它）、命令行 `cli.py`、自动发布（Upload-Post）、一批付费 AI 视频/生图服务的接入（秘塔、OFox、LoomLoom、即梦/火山 Seedance、MuAPI、WaveSpeed、OpenAI 生图）、TwelveLabs 关键词重排等，都在同一套流水线里按配置启用。

## 缩放是怎么实现的

- 外壳页面所有尺寸用 rem，根字号 = 15px × 档位（CSS 变量 `--zoom`）。
- 嵌入的 Streamlit 页面由 `inject.js` 把根字号设为 16px × 档位。Streamlit 的字号、间距、控件高度几乎都用 rem，所以整页跟着缩放。没用 CSS `zoom` 的原因：在容器里实测，CSS zoom 下 Streamlit 下拉菜单的弹出位置会偏开（120% 时偏下约 100 像素，70% 时跑到输入框上方），根字号方式位置正确。
- 档位改变时外壳通过 `postMessage` 通知 iframe；档位存进数据目录的 `shell.json`，下次打开、刷新都保留（窗口端口每次不同，浏览器本地存储会丢，所以存在服务端）。

## 中文化

- 上游界面本身有中文语言包（`webui/i18n/zh.json`），首启时把 `config.toml` 的界面语言设成中文；P4 补丁补齐了 9 个仍是英文的标签。1.0.2 新增的控件（程序生成组、卡片配色、钥匙提示、素材下载代理、语言提醒）文字直接写成中文（在 `svf_ext/`）。
- Streamlit 框架自带的提示（上传框「Drag and drop file here」「Browse files」「… per file」、下拉框「Choose an option」、密码框、帮助按钮、多选标签的无障碍提示等）上游改不了，由 `inject.js` 用对照表在页面里替换，并用 MutationObserver 处理后来出现的元素。只替换 Streamlit 组件自身的文字，不碰你输入的内容、Markdown 正文和代码。唯一的例外：红色出错提示框（`stAlert`）里上游配音失败、素材下载失败的几句固定文字（`failed to synthesize audio; …`、「配音服务未返回试听音频…」、`failed to download video materials from …`），换成中文；后台（`svf_ext`）已经在后面接了「【原因】…」时只换这一句，判断不出原因时补一段常见原因，对照表是 `ALERTS`（1.0.1 加，1.0.2 改为按原因区分）。
- 窗口菜单（macOS 的「退出」「隐藏」「编辑」等）和确认对话框通过 pywebview 的 localization 参数设成中文。
- 仍保留英文的：服务商、模型和产品名（Pexels、API Key、Kimi 等），上游给大模型的英文系统提示词（属于内容，改了会影响生成效果），以及日志。
