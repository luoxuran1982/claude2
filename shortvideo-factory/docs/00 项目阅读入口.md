## 这是什么

「AI 短视频工厂」是把开源项目 MoneyPrinterTurbo（MIT，GitHub 约 13 万星）包成的桌面应用。给一个主题，它让大模型写文案和英文搜索关键词，到 Pixabay / Pexels 等免费素材站下载视频片段拼起来，再配上 Edge TTS 等配音、自动字幕和背景音乐，合成竖屏（抖音、视频号）或横屏短视频。1.0.2 起还可以不用素材：选「知识讲解卡片」，由程序按文案画出图文讲解页（做法借自本仓库的「AI 知识视频工坊」）；1.1.0 起可以让大模型当「导演」先设计分镜（标题、版式、表格等），画面用工坊同款的深色主题。

做这个项目，是为了和本仓库自己做的「AI 知识视频工坊」比较两种思路：一个用网络素材拼接，一个在本机按模板画帧。对比结论和对比实验的步骤在 [04 与 AI 知识视频工坊的对比](<04 与AI知识视频工坊的对比.md>)。

## 1.1.0 更新了什么（2026-10-15）

用户看了 1.0.3 后觉得：「知识讲解卡片」能用，但画面很 low，不如工坊好看。原因是没有「导演」——程序按正则把文案切成句子，用句子开头几个字当标题（会出现「由这三种基本门」这种半截标题），而工坊是让大模型先设计分镜。用户要求几种优化方案**全部做成可选项、现有方案保留**，方便对比，原理在使用指南里讲清楚。1.1.0：

- **视频来源「程序生成」组**：「知识讲解卡片（规则切分）」= 原方案，只改名；新增「**知识讲解卡片（AI 导演）**」——写完文案、配好音后多调用一次你配置的大模型，请它把编号的句子分成若干页，每页给完整短标题、版式（标题、关键词、要点、流程、对比、表格、代码、引言、数字、图表）、结构化数据和对应的句子编号；程序校验 JSON，不合格把原因告诉模型重试一次，还不行退回规则切分并写明原因；每页时间仍按配音和字幕对齐。新增「**知识讲解卡片 + AI 插图**」——导演挑最多 3 页概念页，用「设置 → 素材来源设置」里的 OpenAI 兼容文生图生成插图作背景，没配置时提示并退回纯卡片。「混合」可以选补齐用规则切分还是 AI 导演。见 [01 使用指南](<01 使用指南.md>) 第 2.4 节（每种来源的流程图、钥匙、费用、优缺点、和工坊的异同）。
- **工坊主题**：工坊 `studio/visuals.py` 的深色主题和全部版式（表格逐行出现、代码高亮、流程箭头、对比两栏、要点逐条亮起、关键词大字、引言、图表）完整移植（`svf_ext/studio_cards.py`）；AI 导演默认用它，规则切分也能选，原来三套配色保留。
- **「审片 / 分镜」顶层标签页**：生成完以后一次看完每一页——「审片」网格总览（缩略图、序号和版式名、起止时间、标题、口播文字，点一格成片跳到那一页），「分镜」逐镜详情（大图、画面类型、口播原文和字数、起止时间、对应句子、导演给的结构化数据）。生成页和任务管理里都有入口（补丁 P9）；库存视频来源显示每段素材的缩略帧和关键词。第 2.12 节。
- **「模型调用」顶层标签页**：1.0.3 放在生成页的调用记录搬过来；按时间列出一个任务的每次调用，分块标明「程序发给模型的」（每条 message 原样、标 role，固定模板 / 程序填的变量 / 程序加的要求用颜色区分）、「模型的思考过程」（reasoning_content，可折叠）、「模型返回的内容」、「程序最后怎么用它」、用量和耗时、原始 JSON；标出调用链（上一次的输出出现在下一次输入里的位置）；可复制，没有 API Key。第 2.9 节（含一条逐段解读的例子）。
- **字数控制方式**三档：让大模型自己数（严格，1.0.3 的做法）/ 程序检查（推荐，默认：只给大概字数，程序数完偏差超过 ±15% 再请模型改写一次）/ 不控制。日志解读里显示档位、目标字数和实际字数。第 2.11 节。
- 对上游的改动只多了 P9（`webui/Main.py` 任务管理每行加两个链接）；其余都在外壳里「包一层」。见 [UPSTREAM.md](<../UPSTREAM.md>)。

## 1.0.3 更新了什么（2026-10-15）

用户在 Windows 上实测 1.0.2 后反馈：连按三次「生成视频」起了 3 个任务，多出来的「生成中」任务删不掉也停不下来；「打开目录」仍然没反应；想看懂日志、看到大模型到底收发了什么；没有「视频长度」设置；知识讲解卡片出片太慢（51 秒竖屏，最终渲染 5 分钟以上）。1.0.3：

- **防重复提交、取消任务**：有任务在生成时「生成视频」变成灰色的「生成中…」，连点无效，后台同时到达的几次只放行一个，同一窗口同样参数 90 秒内只保留一个；「任务管理」里生成中的任务有 ⏹「取消」（结束它的 FFmpeg 子进程、状态标「已取消」），取消后能删除；「生成中」但后台没在跑的残留任务（连点留下的、重启前没跑完的）标成「已中断」，可以删除。见 [01 使用指南](<01 使用指南.md>) 第 2.7 节。
- **「打开目录」改由应用主进程打开**：1.0.2 在生成界面后台（没有窗口的 Streamlit 子进程）里调用 `os.startfile`，打开文件夹没反应；现在子进程通过本机 HTTP（`/api/open-path`）请拥有窗口的启动器去打开，只允许数据目录之内的路径；打不开时显示原因、完整路径和「复制路径」按钮。任务管理和「设置 → 缓存管理」两处都改了。
- **日志解读**：原始日志上面按 8 个步骤（写文案 → 提取关键词 → 配音 → 字幕 → 找素材或画卡片 → 处理片段 → 拼接 → 最终渲染）讲清在做什么、为什么、正常要多久、出错常见原因，每条对应原始日志的行号；「still running」解释成「仍在渲染，已用 X 秒」。第 2.8 节。
- **大模型调用记录**：每次调用都记到任务目录的 `llm_calls.jsonl`，界面上可展开：哪一步、哪个服务和模型、完整提示词（system / user 原文）、完整原始输出和原始 JSON、耗时、token 用量；记录里不含 API Key。第 2.9 节。
- **目标时长**：30 / 60 / 90 / 120 秒或自定义，按语速换算成文案字数写进写文案的提示词，生成后显示「目标多少秒、实际多少秒」。第 2.10 节。
- **知识讲解卡片快速通道**：讲解页逐帧画好、字幕直接画进画面，用 FFmpeg 一次合成画面、配音、背景音乐，只编码一次；能用硬件编码器时自动选用，失败回退 libx264。容器里同一段约 47 秒的竖屏文案：1.0.2 流程 205–235 秒 → 1.0.3 33–40 秒。库存视频来源的流程不变。第 2.4 节、[02](<02 软件框架与系统架构.md>)「知识卡片快速通道」。
- 对上游的改动：P5 的打开目录改为经外壳打开；新增 P7（`webui/Main.py`：按钮置灰与提交前检查、任务管理的取消和「已取消/已中断」、日志解读和调用记录的位置、原始日志行号、目标时长控件、打开失败的兜底显示）和 P8（`app/services/task.py`：知识卡片快速通道的入口），都是「能导入 `svf_ext` 就调用，否则保持原样」。见 [UPSTREAM.md](<../UPSTREAM.md>)。

## 1.0.2 更新了什么（2026-10-14）

用户在 Windows 上用 Pixabay 素材已经能出视频，但讲「逻辑门」这类知识主题时，素材库里只搜得到风景、动物，和内容不搭；另外遇到了「打开目录」没反应、选错声音导致「No audio was received」、钥匙填错栏位、Pexels 暂停发新钥匙、需要代理才能下载素材等问题。1.0.2：

- **新视频来源「知识讲解卡片」**（「视频来源」→「程序生成」组，免费、不联网、不需要钥匙）：按配音和字幕的时间把文案分页，用程序画出图文讲解页——标题页、编号要点、对比两栏、流程箭头、关键数字、关键词卡（关键词高亮），按句子特征自动选版式；要点随配音逐条亮起；每页缓慢缩放或平移，换页淡入；配色三选一（课堂蓝、深夜蓝、暖纸）；画面比例跟随所选比例。字幕、配音、背景音乐、拼接照常由上游完成。画法移植自「AI 知识视频工坊」的 `studio/visuals.py`，代码在 `svf_ext/`。
- **「混合」来源**（Pixabay 或 Pexels + 知识卡片）：素材够用就全用素材，搜不到或不够时用卡片补齐，不让任务失败。
- **打开目录**：任务目录、缓存目录的「打开」在 Windows 上静默失败，改成 Windows `os.startfile`、macOS `open`、Linux `xdg-open`（实测在 Windows 上仍然无效，1.0.3 改由应用主进程打开）。
- **声音和文案语言不一致提醒**、**配音失败按原因提示**（403 / No audio received / 网络连不上分开说明）。
- **素材钥匙格式检查和中文原因**：Pixabay「数字-25 位十六进制」、Pexels 约 56 位字母数字；填错栏位提示；Pexels 非 JSON / 401、Pixabay 400 时说明原因。**Pexels 暂停发新钥匙，推荐 Pixabay。**
- **素材下载代理**：「设置 → 素材来源」里填，只有素材搜索和下载走它。
- 对上游的改动：新增两处补丁 P5（`webui/Main.py`）、P6（`app/services/task.py`），都是「能导入 `svf_ext` 就调用，否则保持原样」，见 [UPSTREAM.md](<../UPSTREAM.md>)。用法见 [01 使用指南](<01 使用指南.md>) 第 2.4、2.5 节。

## 1.0.1 更新了什么（2026-10-14）

1.0.0 在 Windows 上实际使用时，DeepSeek 写文案和关键词都成功，但配音失败：界面显示「failed to synthesize audio」，`webui.log` 里连着 3 次 `azure_tts_v1 ... failed, error: 403, message='Invalid response status'`，把声音从 zu-ZA-ThandoNeural 换成中文也一样。原因是微软 Edge 在线朗读接口改了验证方式，1.0.0 随包的 edge-tts 7.2.7（来自上游锁文件）被拒；edge-tts 7.3.0 起改用 Sec-MS-GEC v2 令牌。1.0.1：

- 随包 edge-tts 升到 **7.3.1**（依赖清单生成脚本加了「覆盖上游锁定版本」的机制，原因写在 `packaging/make_runtime_requirements.py`；7.3.1 的依赖锁文件里都满足，没有连带升级）。核对过上游的调用（`voice.azure_tts_v1`：`Communicate(boundary=...)`、`stream()`、`SubMaker.feed/get_srt`）在 7.3.1 下接口没变，不需要改上游代码。
- 默认配音声音改成中文「zh-CN-XiaoxiaoNeural」（晓晓）：新用户首次打开就选好；老用户配置里没有 voice_name 时补上，选过的声音不动。
- 配音失败时，界面红色提示后面补一段中文原因说明（403 多半是接口变更要升级、网络拦截、声音与文案语言不一致，以及怎样换配音引擎）。
- 详见 [01 使用指南](<01 使用指南.md>) 第 5 节「配音失败（403）」和 [UPSTREAM.md](<../UPSTREAM.md>)「依赖的版本」。
