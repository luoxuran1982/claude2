这篇比较两个应用：**AI 短视频工厂**（本项目，内置 MoneyPrinterTurbo 1.3.8，commit `bbe7eb9`）和本仓库根目录的 **AI 知识视频工坊**（`studio/`，0.3.1）。所有结论来自两边的源码（文中注明了文件和函数），没有用真实 Key 实际出片；花费是按源码里的提示词长度和统一假设单价估算的，实测方法见最后一节。

## 一句话结论

- **短视频工厂**＝「大模型写一段口播 + 英文关键词 → 去免费素材站搜实拍片段拼起来 → 配音字幕背景音乐」。快、画面是真实视频、几乎零成本，适合**情绪、生活、风景、泛科普**类短视频；但画面和每句话的对应很松，**数字、公式、代码、图表、人名画不出来**，文案没有事实来源。
- **知识视频工坊**＝「大模型一次写出分镜 JSON（每镜的类型、画面上的字、数据）→ 本机用 Pillow 按 11 种模板画帧 → 配音、按采样数对齐时间轴 → FFmpeg 合成」。画面上的文字和数字由程序画，**不会画错**，有事实清单和合规提示，适合**知识、财经、技术讲解**；但画面是图文卡片而不是实拍，视觉冲击力弱，一条视频要你多花时间审稿。

## 生成思路：网络素材拼接 vs 本地模板画帧

**短视频工厂**（`app/services/task.py: _run_pipeline`）：

```
主题 ──LLM①──► 口播文案 ──LLM②──► 5 个英文搜索词
                  │                        │
                  ▼                        ▼
           Edge TTS 配音 + 逐词时间    Pexels 搜索 → 下载片段（直到时长够）
                  │                        │
                  ▼                        ▼
             SRT 字幕          MoviePy 裁切、切段、拼接、转场
                  └──────────┬─────────────┘
                             ▼
               叠字幕 + 混配音和背景音乐 → FFmpeg 编码 MP4
```

画面先于句子确定：搜索词描述的是「主题大概长什么样」（例如 sleepy person、summer heat），片段按随机或顺序拼到配音长度。画面和每句话之间没有对齐关系。

**知识视频工坊**（`studio/pipeline.py: generate` + `render`）：

```
主题+观点+资料 ──LLM①（一次）──► 分镜 JSON：每镜 type / category / heading / narration / data / image_query
                                        │  （你在分镜页、审片页修改）
                                        ▼
            逐句配音（缓存）→ 采样数定时间轴 → 每句画一帧（模板 + 逐条展开）→ ffconcat → FFmpeg
```

画面由内容决定：模型先给每镜标类别（具体事物 / 抽象概念 / 数据 / 人名机构），只有「具体事物」才去配图，配图分数低于及格线（默认 0.34）就退回文字卡（`images.assign`）。数字和公式由程序按 `data` 字段画出来，不经过任何生成模型。

## 每条视频的模型调用次数和花费

统一假设单价：输入 2 元 / 百万 token、输出 8 元 / 百万 token（这是工坊设置里的默认单价，DeepSeek 一档的价格；其他模型按比例换算）。中文按约 1 字 ≈ 1 token 粗算，英文约 4 字符 ≈ 1 token。

| | 短视频工厂 | 知识视频工坊 |
| --- | --- | --- |
| 默认调用次数 | **2 次**：文案 1 次（`llm.generate_script`）+ 关键词 1 次（`llm.generate_terms`）；失败各自最多重试 5 次 | **1 次**（`prompts.single_call`）；超过 6 分钟的视频改为「大纲 1 次 + 每章 1 次」 |
| 可选的额外调用 | 开自动发布时 +1 次（标题和标签）；用付费 AI 视频/生图时另按秒或按条计费 | 单镜「AI 改写」每次 +1 次小调用；启用「事实核查模型」+1 次 |
| 输入长度 | 文案提示词约 860 字符英文 + 主题 ≈ 250 token；关键词提示词约 700 字符 + 文案 ≈ 600 token；合计约 850 token | 系统提示词约 2070 字 + 主题观点 ≈ 2200 token；加参考资料时每 1 万字约 +1 万 token |
| 输出长度 | 默认 1 段文案约 150–300 字（成片约 30–60 秒）+ 5 个关键词 ≈ 300–450 token | 3 分钟视频口播约 840 字，加上标题、分镜数据、事实清单的 JSON，约 3000–4000 token；思考型模型另加思考 token |
| 单条估算 | 约 0.4–0.6 分钱 | 3 分钟、无参考资料约 3 分钱；带 1 万字资料约 5 分钱；思考型模型可能翻倍 |
| 重复渲染 | 每次「生成视频」都会重新调用（除非文案和关键词已经填好） | 本地缓存相同请求，改画面、重渲染不再调用；系统提示词固定，可命中服务商前缀缓存 |
| 其他花费 | Pexels / Pixabay / Edge TTS 免费 | 系统语音免费；云端 TTS 约 0.2 元 / 5 分钟（工坊 README）；Pexels 免费 |

结论：两边的模型花费都很低，单条都在几分钱以内，**花费不是选择的关键**；短视频工厂更便宜是因为它的视频更短、提示词更短、没有分镜和事实清单。真正的成本差别在**人的时间**：工坊要求你写观点、审事实；工厂几乎一键出片，但出来的内容需要你自己判断能不能发。

## 画面与文字的准确性

| | 短视频工厂 | 知识视频工坊 |
| --- | --- | --- |
| 画面里的文字、数字 | 实拍素材里不会有你要的数字和图表；只有字幕是准确的 | 由 Pillow 按 `data` 字段直接画，文字、代码、公式、数字不会画错（工坊 README「画面模板」） |
| 画面与口播对应 | 弱：关键词描述主题氛围，具体句子常对不上；素材里多为外国场景和人物 | 强：每镜按内容选模板，要点随口播强调；配图有分数门槛，宁可不用图 |
| 事实准确性 | 文案只凭模型知识写，**没有参考资料输入、没有事实核对**；默认提示词要求「直奔主题」，容易出现笼统或过时的说法 | 提示词要求「只用参考资料里的数字和事实」，输出事实清单并标把握度，审片页逐条核对；可再用另一个模型核查 |
| 重复与同质化 | 同一主题多次生成会搜到相似素材 | 同一视频内和最近 30 个项目用过的图不再用；审片页提示「和最近项目结构高度相似」 |

## 配音与字幕

- **自然度**：工厂默认的 Edge TTS 中文神经网络声音比工坊默认的系统语音（婷婷、慧慧）自然得多；工坊换成云端 CosyVoice2 后和 Edge TTS 相当或更好，并支持克隆音色。工厂可选的服务更多（ElevenLabs、MiniMax、Gemini 等）。
- **时间对齐**：工厂用 Edge TTS 的逐词时间戳，字幕可以逐词显示；工坊按句块配音、按采样数精确对齐，字幕和画面共用同一条时间轴，不会漂移，但只到句级。
- **读音**：工坊有「读音替换」（如 `GPU=G P U`，只改配音不改字幕）和审片页的读音清单；工厂只能改文案原文。
- **离线**：工坊的系统语音完全离线；工厂默认的 Edge TTS 必须联网，是微软的非官方接口。

## 适合的题材

| 题材 | 更适合 | 原因 |
| --- | --- | --- |
| 情绪、励志、生活方式、旅行风景、美食氛围 | 短视频工厂 | 实拍素材好看，文案短，不需要精确信息 |
| 泛科普（「为什么夏天容易犯困」） | 都可以；工厂更快，工坊更可信 | 工厂画面更吸引人，工坊能把原因做成流程图和要点 |
| 财经、投资、政策解读 | 知识视频工坊 | 需要数字、图表、事实核对和合规提示；工厂的实拍素材无法表达数据 |
| 编程、技术原理、数学 | 知识视频工坊 | 代码、公式、流程图只有模板画得出来 |
| 产品对比、榜单、清单 | 知识视频工坊 | 表格、对比、要点模板 |
| 批量账号、海外短视频（英文） | 短视频工厂 | 多语言、一次多条、可自动发布（注意平台规则） |

## 各自的优缺点

**短视频工厂（MoneyPrinterTurbo）**

- 优点：一键出片，几分钟一条；实拍画面观感好；配音服务多、默认免费；字幕样式丰富（描边、背景、入场动画、逐词）；支持多比例、一次多条、转场；生态成熟（13 万星，持续更新，测试覆盖率要求 70%）。
- 缺点：画面与内容只在主题层面相关；不能表达数据、代码、图表；文案无事实依据、无合规检查；素材同质化，原创度低；依赖重（安装包 macOS dmg 约 430 MB、Windows Setup 约 130 MB（安装后约 600 MB–1 GB））；界面选项极多、混着大量付费服务和推广链接，新手容易迷路；默认配音必须联网。

**知识视频工坊**

- 优点：画面上的字和数字准确；分镜级控制，审稿环节完整（事实清单、合规、读音、配错图）；一次调用出全部结果，有缓存，花费可见；横竖两版和精简版一次做好；作者观点和 AI 声明内置；体量小、离线能力强。
- 缺点：画面是静态图文卡（逐条展开，不是连续动画），视觉冲击力弱于实拍；需要你提供观点和资料、花时间审稿；系统语音不够自然；配图依赖你自己积累素材库；没有逐词字幕和入场动画。

## AI 知识视频工坊值得借鉴的地方

从 MoneyPrinterTurbo 的源码里能直接参考的做法（按投入产出排序）：

1. **Edge TTS 的逐词时间戳**（`voice.azure_tts_v1` + `SubMaker`）：工坊已支持 edge-tts，但只用整句音频。拿到逐词边界后可以做逐词高亮字幕、更细的要点展开时机。
2. **素材视频片段作为「配图」的一种**：对 `category=concrete` 的镜头，除了图片也允许 Pexels **视频**片段（`material.search_videos_pexels` 的筛选逻辑：按比例、最低分辨率、时长），比静态配图生动；仍保留工坊的分数门槛。
3. **素材搜索缓存与并发下载**（`material._search_videos_with_cache`、`material_cache.py`、`_download_materials_in_parallel`）：缓存键、过期、并发上限和限流处理写得很完整，可直接借鉴到工坊的 Pexels 拉取。
4. **字幕样式**：描边、圆角半透明背景、入场弹簧动画（`video._apply_subtitle_spring_animation`）、字体是否支持当前文字的检测（`video.subtitle_font_supports_text`）——最后这项能避免选了不含中文的字体时出现方框。
5. **多家大模型的注册表**（`app/models/llm_provider.py: LLM_PROVIDER_REGISTRY`）：每家服务商的默认接口、默认模型、申请 Key 的网址集中维护，界面和配置都从这一张表生成。工坊的 `PRESETS` 可以扩展成这样，并在设置页显示「去哪申请」。
6. **配置写入不阻塞长任务**（`config.update_config_nonblocking`、`runtime_config_lock`）：生成过程中改设置不会让页面卡住，也不会中途换模型。
7. **转场和多比例输出**（`video.combine_videos`、`app/services/utils/video_effects.py`）：工坊目前只做横版和竖版；可以加 1:1 和简单转场（淡入淡出）让镜头切换不那么生硬。
8. **按文案顺序生成关键词**（`llm.generate_terms(match_script_order=True)`）：让配图搜索词和叙事顺序一致，工坊的 `image_query` 已是逐镜的，这条主要说明思路一致。
9. **测试覆盖要求**：上游 CI 要求分支覆盖率 ≥ 70%，大量针对竞态、重定向、部分失败的回归测试，值得工坊参考来补测试。

反过来不建议照搬的：自动发布（平台规则风险）、随机拼接素材（与工坊「宁可没图也不要错图」的原则冲突）、把付费服务和推广链接塞进主界面。

## 用同一个主题两边各跑一次（对比实验步骤）

准备：同一个大模型（例如 DeepSeek，同一个 Key），Pexels Key，同一首背景音乐（两边都放一份）。主题建议选一个两边都能做的泛科普题，例如「为什么夏天容易犯困」，目标时长 1 分钟。

**A. AI 短视频工厂**

1. 「设置 → 大模型设置」选 DeepSeek，填 Key，测试连接；「素材来源设置」填 Pexels Key。
2. 视频主题填「为什么夏天容易犯困」，语言 zh-CN，「高级脚本设置」段落数 2（约 1 分钟）。
3. 视频比例竖屏 9:16，配音选一个 zh-CN 女声，背景音乐选指定文件，字幕默认。
4. 点「生成视频」，用手机秒表记录从点击到出片的时间；在服务商控制台记下这次的 token 用量和费用（调用次数应为 2）。
5. 打开任务文件夹，保留 `final-1.mp4`、`script.json`。

**B. AI 知识视频工坊**

1. 设置里选 DeepSeek 预设，填同一个 Key；配音选 edge-tts（和工厂同一个声音更公平）或云端 TTS；背景音乐选同一首。
2. 创作页：主题同上，时长 1 分钟，写 3 句你自己的观点；参考资料粘贴一段权威来源（例如某医院科普文章）。
