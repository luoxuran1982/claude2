| 部分 | 目录 | 谁写的 | 应用内「使用指南 → 源码」 |

## 阅读路线

建议顺序：「软件用途与框架 → 系统架构 → 源码 → 操作与结果」。先读 [02 软件框架与系统架构](<02 软件框架与系统架构.md>) 的进程图和调用链，再按下面顺序读源码。

**外壳（约 1500 行 Python + 900 行 JS）**

1. `svf/__init__.py`、`svf/paths.py`：名字、版本、各部件和数据目录在哪。先弄清「源码运行」和「安装包」两种情况下文件的位置差别。
2. `svf/app.py`：`Shell.main` 是总流程（清理遗留 → 准备数据 → 起服务 → 起后台 → 开窗口 → 收尾），`shutdown` 是退出收尾。
3. `svf/supervisor.py`：`WebUI.start / _wait_ready / stop`，以及 Windows 作业对象 `_WinJob`、`cleanup_stale`。这是「关窗即停止全部后台」的核心。
4. `svf/child.py`：后台进程的入口和看门狗，配合 3 看。
5. `svf/server.py`：先看文件末尾 `make_app` 的路由表，再看 `ProxyHandler.proxy`（流式 HTTP 代理、首页注入）和 `WSProxyHandler`（WebSocket 双向转发）。
6. `svf/userdata.py`、`svf/procinfo.py`、`svf/guide.py`：首启配置、运行状态、使用指南的白名单。
7. `svf/web/index.html` → `app.js`（栏目、缩放、视频生成页、运行状态）→ `guide.js` → `inject.js`（在 Streamlit 页面里做的三件事）。
8. `packaging/build.py`（打包）、`packaging/smoke.py`（CI 冒烟），最后 `tests/`。

**上游（约 3.5 万行，挑主干读）**

1. `upstream/webui/Main.py`：界面。8000 多行，大部分是各家服务商的设置面板；主流程从文件末尾的页面布局往上看，找「生成视频」按钮。
2. `upstream/app/services/webui_task.py`：界面怎样把任务交给后台线程（同时 1 个）。
3. `upstream/app/services/task.py: _run_pipeline`：流水线总控，依次调用下面几个模块。
4. `upstream/app/services/llm.py`：`generate_script`（文案）、`generate_terms`（英文搜索词）、`_generate_response`（各家模型的适配）。提示词就在文件开头。
5. `upstream/app/services/voice.py`：`tts` → `azure_tts_v1`（edge-tts）等配音引擎。
6. `upstream/app/services/material.py`：`search_videos_pexels / pixabay`、`download_videos`。
7. `upstream/app/services/video.py`：`combine_videos`（拼接）、`generate_video`（字幕、配音、背景音乐、编码）。
8. `upstream/app/config/config.py`、`app/utils/utils.py`：配置和目录（P1、P2 补丁在这里）。

## 从源码运行

需要 Python 3.11（与上游一致）。

```bash
cd shortvideo-factory
python3.11 -m venv .venv
. .venv/bin/activate                  # Windows：.venv\Scripts\activate
pip install -r requirements.txt -r requirements-runtime.txt
python run.py                         # 独立窗口
python run.py --browser               # 默认浏览器
python run.py --serve-only --port 18700   # 只起服务（打印地址和令牌），测试用
```

源码运行时数据目录和安装版相同（可用环境变量 `SVF_DATA_DIR` 换到别处），生成界面后台用当前 Python（可用 `SVF_PYTHON` 指定另一个）。

## 修改与重建

| 想改什么 | 改哪里 | 还要同步 |
| --- | --- | --- |
| 顶栏、使用指南、运行状态的界面 | `svf/web/` | `docs/` 对应说明、截图 |
| Streamlit 里又冒出英文 | `svf/web/inject.js` 的 `EXACT` / `PATTERNS` | — |
| 上游界面的中文译文 | `upstream/webui/i18n/zh.json` | `UPSTREAM.md` 补丁表、重新生成 `upstream-patches.diff` |
| 默认配置（首启） | `svf/userdata.py: initial_config_text` | 01 使用指南 |
| 进程启停、退出收尾 | `svf/supervisor.py`、`svf/app.py`、`svf/child.py` | 02 架构、`tests/test_shell.py` |
| 依赖版本 | 重新生成 `requirements-runtime.txt`（`packaging/make_runtime_requirements.py`） | `UPSTREAM.md` |
| 版本号 | `svf/__init__.py` 的 `__version__` | README、docs 的 version 字段 |

每次修改程序，都要在同一次推送里同步更新 `docs/`（它就是应用内「使用指南」的来源）、版本号，并让 CI 重新构建两个平台的安装包。

## 打包（重建安装包）

在哪个系统上运行就打出哪个系统的安装包。正式安装包由 GitHub Actions 构建（`.github/workflows/shortvideo-factory.yml`），本地构建方法：

```bash
cd shortvideo-factory
pip install -r requirements.txt pyinstaller pillow uv
# Windows 另装 NSIS：choco install nsis
python packaging/build.py
python packaging/smoke.py        # 冒烟测试
```

`build.py` 的步骤：

1. `make_icon.py` 画图标（png / ico / icns）。
2. `build_runtime`：`uv python install 3.11` 下载 python-build-standalone（可重定位的 CPython），复制到 `build/payload/runtime/`，删掉用不到的标准库（test、tkinter、idlelib 等）和 `EXTERNALLY-MANAGED` 标记，用 `uv pip install` 按 `requirements-runtime.txt` 装依赖，再验证关键模块能导入、FFmpeg 能运行。
3. 复制上游（去掉测试、Docker、文档图片等）、开源字体、`svf/child.py`（改名 `svf_child.py`）、使用指南资料到 `build/payload/`；用随包 Python 预编译全部 `.pyc`（`unchecked-hash` 模式，不依赖文件时间）；检查不能出现商业字体和来源不明的音乐。
4. PyInstaller 打启动器（`run.py` → ShortVideoFactory，onedir、windowed，带 `svf/web/`）。
5. macOS：把 payload 放进 `.app/Contents/Resources/payload/`，改 Info.plist（名称、版本、允许本机网络），`codesign --force --deep --sign -` 临时签名，打 dmg（里面附「应用程序」快捷方式和使用指南）。
6. Windows：把 payload 放进 `dist/ShortVideoFactory/payload/`，打免安装 zip，用 `installer.nsi` 打 Setup.exe。

产物：`dist/ShortVideoFactory-<版本>-macOS-arm64.dmg`；`dist/ShortVideoFactory-Setup-<版本>-x64.exe` 和 `dist/ShortVideoFactory-<版本>-windows-x64.zip`。CI 上传的产物名为 `ShortVideoFactory-macOS-arm64`、`ShortVideoFactory-windows-x64`。发布到 Releases 用仓库的「发布安装包」工作流（`release.yml`），标签 `shortvideo-factory-v<版本>`。

## 升级上游

步骤见 [UPSTREAM.md](<../UPSTREAM.md>) 的「怎样升级到上游新版本」。要点：先提交原样副本，再逐条重打 P1–P4 补丁，重新生成依赖清单和 `upstream-patches.diff`，跑测试和界面检查，看 Streamlit 有没有新的英文提示要补对照表。
