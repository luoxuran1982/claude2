## 覆盖范围

- **手写源码（研究台外壳）**：`run.py`、`qlibstudio/` 下全部 `.py`、`qlibstudio/web/` 下的 html / js / css / svg、`packaging/`、`tests/`、
  `requirements.txt` 和 CI 工作流（仓库 `.github/workflows/qlib-studio.yml`，安装包里是 `ci/qlib-studio.yml`）。约 6500 行。
  其中 `qlibstudio/data/readers.py`、`adjust.py`、`market.py`、`demo.py` 原样复制自用户自己的 QuantLab 1.1.0（只改了 import 路径），
  `procinfo.py`、`guide.py`、`web/zoom.js`、`web/md.js`、`web/guide.js` 改自同仓库的「热点雷达」。
- **上游**：`upstream/` 是 Qlib 0.9.8 的源码副本（约 600 个文件，其中 qlib 包约 5.7 万行 Python），只读参考 + 运行时导入；改动见 [UPSTREAM.md](<../UPSTREAM.md>)。
- **不算源码、不在「源码」列表里**：`qlibstudio/web/vendor/echarts.min.js`（第三方压缩库，Apache-2.0，许可证在同目录）、
  编译产物（`upstream/qlib/data/_libs/*.so|*.pyd|*.cpp`）、`build/`、`dist/`。

应用内「使用指南」左侧「源码」里能逐个只读查看上面列出的全部文件，「下载全部源码（zip）」得到和仓库 `qlib-studio/` 相同的目录结构。

## 源码阅读路线

**研究台外壳**（约 1–2 小时）：

1. `run.py` → `qlibstudio/app.py`：程序怎么启动、窗口怎么开、退出时做什么。
2. `qlibstudio/server.py`：界面能调哪些接口；`do_POST` 开头的安全校验。
3. `qlibstudio/jobs.py` → `worker.py`：任务怎么放进独立进程、进度怎么回来、取消怎么做。
4. `qlibstudio/data/convert.py`（配合 02 篇的字段表）→ `quality.py`：数据怎么变成 Qlib 格式。
5. `qlibstudio/experiment.py`：最重要的一篇，看它怎么组织 Qlib 的各个组件。
6. `qlibstudio/compare.py`：交换格式。
7. `qlibstudio/web/app.js`：界面上每个按钮对应哪个接口。

**上游 Qlib**（按研究台用到的顺序）：

1. `qlib/__init__.py`（`init`）→ `qlib/config.py`（默认配置、`REG_CN` 的 A 股设定）。
2. `qlib/data/data.py`（`D.calendar / D.instruments / D.features`，`LocalProvider` 读 `.bin`）→ `qlib/data/storage/file_storage.py`。
3. `qlib/data/ops.py`（表达式算子：`Ref`、`Mean`、`Std`、`Corr`、`Rsquare`…）→ `qlib/data/_libs/rolling.pyx`（Cython 滚动计算）。
4. `qlib/contrib/data/loader.py`（`Alpha158DL.get_feature_config`：158 个因子表达式怎么生成）→ `qlib/contrib/data/handler.py`（`Alpha158`、`Alpha360`）。
5. `qlib/data/dataset/handler.py`（`DataHandlerLP`：raw / infer / learn 三份数据）→ `qlib/data/dataset/processor.py`（`RobustZScoreNorm`、`CSZScoreNorm`、`Fillna`…）→ `qlib/data/dataset/__init__.py`（`DatasetH.prepare`）。
6. `qlib/contrib/model/gbdt.py`（`LGBModel.fit / predict`），对照 `xgboost.py`、`catboost_model.py`、`linear.py`。
7. `qlib/contrib/strategy/signal_strategy.py`（`TopkDropoutStrategy.generate_trade_decision`）。
8. `qlib/backtest/__init__.py`（`backtest`、`get_exchange`）→ `exchange.py`（涨跌停、成交价、一手、费用）→ `account.py`、`position.py`、`report.py`（每日报告、订单指标）。
9. `qlib/contrib/eva/alpha.py`（`calc_ic`）、`qlib/contrib/evaluate.py`（`risk_analysis`）。
10. `scripts/dump_bin.py`（`DumpDataAll`）、`scripts/data_collector/crowd_source/README.md`（社区数据集）。
11. 想看上游原本怎么跑：`examples/workflow_by_code.py`、`examples/benchmarks/LightGBM/workflow_config_lightgbm_Alpha158.yaml`。

## 怎么改

| 想做的事 | 改哪里 |
| --- | --- |
| 加一个模型（比如上游的 `DEnsembleModel`） | `experiment.py`：`MODELS`、`MODEL_PARAMS`、`make_model`、`fit_kwargs`；界面下拉框自动从 `/api/catalog` 读 |
| 加因子集（如 `Alpha158vwap` 或自定义表达式） | `experiment.py`：`FACTOR_SETS`、`make_handler`；自定义表达式可以写一个 `DataHandlerLP` + `QlibDataLoader(config={"feature": [...]})` |
| 改回测规则（费率、涨跌停、成交价） | `experiment.py`：`DEFAULTS`、`limit_threshold`、`backtest` 的 `exchange_kwargs`；界面字段在 `index.html` 和 `app.js` 的 `expConfig` |
| 加数据来源 | `qlibstudio/data/` 新写一个读取函数，返回 `readers.Series` 列表；`worker.execute` 加一个任务种类，`jobs.KINDS` 登记；界面在「获取数据」加一个分页 |
| 改交换格式 | `compare.py`（`export_from_result`、`validate`，`VERSION` 加 1）；同步改 04 篇「交换格式」和 `samples/` 样例，并通知 QuantLab 一侧 |
| 改界面文字或布局 | `qlibstudio/web/`；所有尺寸用 rem，缩放才能整体生效 |

改完要同步：文档（`docs/`，也就是应用内使用指南）、`qlibstudio/__init__.py` 的版本号、截图；然后跑测试、推送，CI 重新构建两个平台的安装包。

## 从源码运行

需要 Python 3.12 和 C++ 编译器（macOS：`xcode-select --install`；Windows：Visual Studio Build Tools 的「使用 C++ 的桌面开发」）。

```bash
cd qlib-studio
python -m venv .venv && source .venv/bin/activate      # Windows：.venv\Scripts\activate
pip install -r requirements.txt
python packaging/build_ext.py                          # 编译上游两个 Cython 扩展，只需一次
python run.py                                          # 应用窗口
```

想用深度模型：额外 `pip install torch`，然后在 `upstream/` 里按上游文档用 `qrun examples/benchmarks/LSTM/workflow_config_lstm_Alpha158.yaml`
（需要上游格式的数据目录，可以把研究台的 `datasets/<编号>/` 作为 `provider_uri`）。研究台界面本身不调用深度模型。

## 测试

```bash
python -m unittest discover -s tests -v        # 外壳：20 项，含真实跑 Qlib 实验，约 1–3 分钟
node tests/web.test.js                          # 缩放档位、Markdown
cd upstream/tests && PYTHONPATH=.. python -m pytest -q misc/test_index_data.py misc/test_sepdf.py misc/test_utils.py security \
   test_structured_cov_estimator.py backtest/test_soft_topk_strategy.py backtest/test_soft_topk_strategy_cold_start.py \
   data_mid_layer_tests/test_processor.py ops/test_special_ops.py \
   --ignore=security/test_eval_registries.py --ignore=security/test_artifact_trust_api.py   # 上游离线可跑的部分，约 550 项
python packaging/smoke.py --source              # 冒烟（同 CI）
```

上游其余测试要下载 Qlib 官方数据（`GetData().qlib_data`，目前暂停提供）或需要 PyTorch / plotly（研究台不装），没有放进 CI。

## 打包和发布

| 平台 | 命令 | 产物 |
| --- | --- | --- |
| macOS（Apple 芯片） | `pip install -r requirements.txt pyinstaller pillow && python packaging/build_ext.py && python packaging/build.py` | `dist/Qlib 量化研究台.app`、`dist/QlibStudio-1.0.0-macOS-arm64.dmg` |
| Windows | 同上，另需 NSIS（`choco install nsis`） | `dist/QlibStudio-Setup-1.0.0-x64.exe`、`dist/QlibStudio-1.0.0-windows-x64.zip` |

`build.py` 做的事：画图标 → 把使用指南清单里的全部文件（文档、附件、手写源码、上游源码）复制到 `build/project/` 打进包 →
逐个导入上游 qlib 模块，能导入的都列为隐藏导入（上游按字符串动态加载模块，静态分析找不全）→ PyInstaller 单目录打包 →
macOS 写 Info.plist、临时签名、做 dmg；Windows 打免安装 zip 和 NSIS 安装程序（CI 上找不到 makensis 直接失败）。

CI：仓库 `.github/workflows/qlib-studio.yml`。只有 `qlib-studio/` 或这个工作流有改动时才运行：Ubuntu 上跑全部测试和源码冒烟，
再在 Windows、macOS 上打包并对安装包冒烟；产物保留 7 天。发布用仓库的「发布安装包」工作流（`release.yml`），把通过的那次构建原样发布成 Release，标签 `qlib-studio-v<版本>`。

## 升级上游 Qlib

1. `git clone https://github.com/microsoft/qlib` 到临时目录，`git checkout <新标签>`，`git archive HEAD | tar -x -C qlib-studio/upstream-new`。
2. 按 UPSTREAM.md「没有带过来的文件」删掉图片和 `.pkl`；把 `qlib/_version.py` 复制过去并改版本号。
3. 检查「运行时替换」的对象还在不在：`scripts/dump_bin.py` 里的 `ProcessPoolExecutor`、`qlib.workflow.QlibRecorder.log_metrics`、
   `qlib.init` 的 `kernels` 参数、`Exchange` 的 `limit_threshold` 表达式写法、`Indicator.order_indicator_his`。
4. 用 `upstream-new` 替换 `upstream`，`python packaging/build_ext.py`，跑全部测试和冒烟。
5. 更新 `qlibstudio/__init__.py` 的 `UPSTREAM_VERSION / UPSTREAM_COMMIT`、`UPSTREAM.md`、`guide.js` 里的版本文字、本文档，递增研究台版本号。
