本篇比较两个都能「用本地 A 股日线做机器学习选股 + 回测」的项目：

- **QuantLab 量化学习实验室 1.1.0**：用户自己的项目（仓库分支 `claude/quant-ml-lab` 的 `quant-lab/`），从零手写的一整套流程，约 3600 行 Python + 1500 行界面代码。
- **Qlib 量化研究台 1.0.0**：本项目，计算全部交给微软 Qlib 0.9.8（`upstream/`，qlib 包约 5.7 万行 Python），外面包一层桌面外壳。

对比基于两边实际的源码（文中注明文件和函数），不是基于宣传材料。演示数据上的数字只用来说明「同数据同区间」怎么比，不代表任何真实策略。

## 一句话结论

QuantLab 是「**为 A 股日线选股量身定做、规则写得很细**」的小而全工具：交易规则（T+1 开盘、一字涨跌停、最低 5 元佣金、印花税、滑点、退市清算）、
防未来函数（隔离带、只用样本外预测）、早停指标（验证集 RankIC）都贴着 A 股实际。
Qlib 是「**通用的量化研究平台**」：数据格式和表达式引擎、几十种模型（含深度模型）、嵌套执行、在线滚动、元学习都有，
学术基准齐全，但 A 股细节默认比较粗（统一 ±9.5% 涨跌停、收盘价成交、没有滑点和退市清算），而且需要你自己准备数据、写配置。
两者最值得互相借鉴的：QuantLab 学 Qlib 的**表达式因子 + 数据格式 + 模型基准**，Qlib（研究台）学 QuantLab 的**A 股成交规则和 RankIC 早停**。

## 分项说明

### 数据

两边读取本地文件的代码完全相同（研究台的 `data/readers.py`、`adjust.py`、`market.py` 原样复制自 QuantLab），所以同一份通达信目录导入后，
不复权价、除权日估算、复权因子都一样。差别在存储：

- QuantLab 把整个数据集存成一个 parquet，每次实验载入成「日期 × 股票」宽表，因子在宽表上向量化计算，简单直接，几百到几千只股票都够快；
- Qlib 把数据拆成「每只股票每个字段一个二进制文件」，按需读取，适合几千只股票、十几年、分钟级别的数据，还能缓存表达式结果。代价是要先转换（`dump_bin`），看不出原始表格。

研究台额外接了两个来源：**富途 OpenD**（带额度管理和增量缓存）和**社区数据集**（已经是 Qlib 格式，含已退市股票，能缓解幸存者偏差）。
QuantLab 1.2.0 计划也加上 AKShare 和富途下载（另一个任务）。

### 因子

- QuantLab 的 73 个因子每个都有中文说明，覆盖了 A 股常用的技术指标（RSI、MACD、KDJ、布林带等）和市场相对因子（Beta、特质波动、相对强弱），还有「20 日涨停次数」这类 A 股特有因子；有「截断一致性」测试保证不用未来数据。
- Qlib 的 Alpha158 是一套系统化生成的量价因子：同一组算子（均值、标准差、斜率、R²、残差、最大最小、分位数、相关、涨跌计数等）乘以 5 个窗口，没有经典技术指标，但覆盖面更「均匀」，是学术论文的通用基线。Alpha360 干脆不做特征工程，把 60 天原始价量交给模型（主要给深度模型用）。
- Qlib 的因子都是字符串表达式，加一个因子只要写一行 `"Mean($close, 5)/$close"`；QuantLab 要写一个 Python 函数。

### 模型与训练

- QuantLab 的亮点是**为选股目标调过**：LambdaRank 排序目标、分类目标、早停看验证集 RankIC、训练只用次日能买进的样本、多模型按排名集成。
- Qlib 的模型接口统一（`fit(dataset)` / `predict(dataset)`），基准参数来自上游 `examples/benchmarks`（在沪深 300 / 中证 500 上调的），换到几十只股票的小数据集上正则化偏强，常常几轮就早停（研究台报告「训练」页会显示最佳轮数）。
- 滚动训练：QuantLab 默认就是 walk-forward 且有隔离带，**更严格**；Qlib 默认一次切分，研究台提供滚动选项但不留隔离带（标签周期 1 天时几乎没有影响）。

### A 股交易规则与回测假设

这是两边差别最大的地方，也是同样的预测在两边回测结果不同的主要原因：

| 规则 | QuantLab | Qlib（研究台默认） | 对结果的影响 |
| --- | --- | --- | --- |
| 成交时点 | t+1 开盘 | t+1 收盘（可改开盘） | 收盘成交假设你能在收盘前按收盘价成交，偏乐观 |
| 涨跌停判断 | 开盘价相对前收是否到涨跌停价 | 收盘涨跌幅是否到按板块的涨跌停幅度（选开盘成交时用开盘价） | QuantLab 更贴近「一字板买不进」的实际 |
| 买不进时 | 顺延买下一只 | 少买一只 | QuantLab 资金利用率更高 |
| 滑点 | 单边 0.1% | 无 | 换手高时差别明显（Qlib 结果偏乐观） |
| 印花税 | 0.05%（2023-08-28 起的税率） | 卖出 0.15% 里含 0.1%（旧税率） | Qlib 示例口径偏保守 |
| 调仓 | 每 5 天，缓冲带 1.5 倍 | 每天，最多换 n_drop 只 | 两种控制换手的方法 |
| 资金 | 全部资金等权 | 95% 资金 | |
| 退市 | 最后收盘价清算 | 卡住按最后价格估值 | 退市多的数据集上 Qlib 可能高估 |

### 指标

收益口径不同，**不能直接拿两边各自的「年化」比**：QuantLab 用复利年化（244 天）；Qlib 官方基准表用「超额收益按日相加 × 238」。
研究台报告里两种都给（「年化收益」是复利口径，「超额年化（Qlib 口径）」是上游口径），对比页按共同区间用同一个公式重算。
IC 的频率也不同：QuantLab 每 5 天一个，Qlib 每天一个；均值可比，IR 不能直接比（样本数不同）。

### 界面和易用性

| | QuantLab | 研究台 |
| --- | --- | --- |
| 上手 | 打开就能生成演示数据、跑实验；参数说明写在表单旁 | 同样；多了数据质量检查和四种数据来源 |
| 结果 | 实验结果页指标很全，有月度收益表、交易统计、因子重要性、最新选股 | 净值 / 回撤 / IC / 分层 / 持仓 / 成交 / 训练过程 |
| 研究功能 | 单因子检验、实验对比、命令行批量 | 和 QuantLab 并排对比；可切换 Qlib 的多种模型 |
| 扩展 | 改 Python 源码 | 改外壳，或直接用上游 Qlib 的配置体系（深度模型、在线滚动等） |
| 安装包 | 较小（不含 Qlib、XGBoost、CatBoost） | 较大（300–500 MB 量级，含 Qlib 依赖） |

## 各自的优缺点

**QuantLab**

- 优点：A 股规则细（开盘涨停判断、滑点、退市清算、最低佣金、现行印花税）；防未来函数做得严（隔离带、截断一致性测试、只用样本外预测回测）；早停和目标函数对准选股排序；因子有中文解释；有单因子检验和最新选股；代码量小，容易读懂和改。
- 缺点：因子要一个个手写；只有树模型、线性和小型 MLP；数据存成单个 parquet，股票多、年限长时内存压力大；任务在主进程线程里跑，取消要等下一次进度回调，内存要等垃圾回收；没有统一的数据格式，换别的工具要重新导出。

**Qlib（研究台）**

- 优点：工业级的数据格式和表达式引擎；Alpha158 / Alpha360 是业界通用基线，结果能和论文、基准表对照；模型多（含深度模型、集成、元学习）；回测框架通用（嵌套执行、多频率）；社区数据集能直接用；研究台把它做成了点按钮就能跑、能看图的形式。
- 缺点：A 股细节默认粗（统一 9.5% 涨跌停、收盘成交、无滑点、无退市清算、旧印花税）；早停看 L2 不看 RankIC；默认参数为大股票池调的，小数据集上容易「几轮就停」；体积大、依赖多；上游有些接口和新版 pandas 不兼容（例如订单指标的 `to_series()`，研究台已绕开）。

## QuantLab 值得借鉴的清单（从 Qlib）

1. **表达式因子**：加一个小型表达式解析（或直接引入 Qlib 的表达式写法），让用户在界面上写 `Mean($close,5)/$close` 自定义因子，不用改代码。
2. **把 Alpha158 作为一组可选因子**：和自己的 73 个因子并列，方便对照「手写因子 vs 通用基线」。
3. **数据导出成 Qlib 格式**：QuantLab 的数据集可以一键导出成 Qlib 目录（研究台的 `convert.build` 可以直接复用），以后能用 Qlib 的全部模型。
4. **更多模型**：XGBoost、CatBoost 接口和 LightGBM 几乎一样，成本很低；深度模型可以作为可选插件。
5. **每日 IC**：除了每 5 天一个的决策日 IC，再给每天的 IC，样本更多、曲线更平滑。
6. **社区数据集**：含退市股票，可以作为 QuantLab 的一个数据来源，缓解幸存者偏差。
7. **任务放进独立进程**：长时间训练时内存能完全释放，取消立即生效。
8. **交换格式导出**（QuantLab 1.2.0 计划中）：按本篇「交换格式」一节输出，就能和研究台并排对比。

反过来，研究台下一步可以从 QuantLab 学：开盘涨跌停判断 + 买不进顺延、滑点、退市清算、现行印花税；早停改用验证集 RankIC；
训练集与测试集之间留隔离带；单因子检验页；最新选股页。

## 同数据同区间对比步骤

目标：同一份数据、同一段样本外区间，两边各跑一次，在研究台的「与 QuantLab 对比」页并排看。

1. **准备同一份数据**（三选一）：
   - 演示数据：两边用的是同一个生成器。QuantLab「数据中心 → 生成演示数据」选 300 只、6 年；研究台「数据 → 演示数据」也填 300 只、6 年（随机种子默认都是 7、结束日都是 2026-09-30），生成的行情完全相同。
   - 自己的通达信目录：两边导入同一个 `vipdoc`（读取代码相同）。
   - 富途数据：先在研究台下载，再把缓存目录 `futu-cache/` 里的 CSV 导入 QuantLab（列名 date/open/high/low/close/volume/amount/factor，QuantLab 能识别 `factor` 列为复权因子）。
2. **在 QuantLab 跑实验**：例如 LightGBM、预测 5 天、前 20 只、每 5 天调仓（默认设置）。记下实验结果页显示的样本外区间（例如 2022-05-25 ~ 2026-09-29）。
3. **在研究台跑实验**：测试区间设成和 QuantLab 的样本外区间一样；为了接近 QuantLab 的设置，可以选「成交价：开盘价」「预测周期：5」「topk 20」「勾选滚动训练，每 63 天」。
4. **把 QuantLab 的结果拿过来**：QuantLab 1.2.0 起用「导出实验结果」生成交换格式 JSON，在研究台「与 QuantLab 对比 → 导入 QuantLab 结果文件」；
   QuantLab 还是 1.1 时，在对比页展开「直接读它的实验目录」，填 QuantLab 数据目录下的 `runs/<编号>/`。
5. **勾选两项 → 对比所选**：保持「收益指标按共同区间重新计算」打勾，表里上半部分是同一公式在共同区间上的数（可以直接比），下半部分是各自文件里的原始数（口径不同，仅供参考）；
   下面是净值、相对基准、RankIC 20 期均值三张图，最后是设置对照表。
6. 看差别时先看「设置对照」：成交价、调仓、费用、涨跌停规则不同，收益就会不同；IC 的差别更能反映「预测本身」的好坏。

### 示例：演示数据上的一次对比（容器里实测）

同一份演示数据（两边生成器相同：300 只、6 年、随机种子 7，2021-01 ~ 2026-09），QuantLab 用默认设置
（LightGBM、73 个因子、预测 5 天、前 20 只、每 5 天调仓、T+1 开盘、滚动训练），研究台跑了两种设置，
测试区间都对齐到 QuantLab 的样本外起点 2022-02-23，按共同区间 2022-02-23 ~ 2026-09-23（1196 个交易日）用同一公式重算：

| | QuantLab 默认 | 研究台：Qlib 默认口径 | 研究台：接近 QuantLab 的设置 |
| --- | --- | --- | --- |
| 关键设置 | 5 日标签、每 5 天调仓、T+1 开盘、滑点 0.1%、印花税 0.05% | Alpha158、1 日标签、每天 TopkDropout（20 只、换 2 只）、收盘成交、无滑点 | Alpha158、5 日标签、TopkDropout（20 只、换 4 只）、开盘成交、无滑点 |
| 训练 | 750 天滑动窗口、每 63 天重训、隔离带 6 天 | 扩展窗口、每 63 天重训 | 同左 |
| RankIC 均值（各自原始） | 0.029（每 5 天一个） | 0.018（每天一个，1 日收益） | 0.030（每天一个，5 日收益） |
| 累计收益 | 132% | 264% | 358% |
| 年化收益（复利） | 18.8% | 30.1% | 36.4% |
| 最大回撤 | −34.8% | −29.7% | −28.5% |
| 夏普 | 0.81 | 1.23 | 1.40 |
| 年化超额（相对各自的等权基准） | −7.6% | +3.8% | +10.1% |

怎么读：

- **预测能力差不多**：同样是 5 日收益，QuantLab 的 RankIC 0.029 和 Qlib Alpha158 + LightGBM 的 0.030 几乎一样——手写的 73 个因子和 Alpha158 在这份模拟数据上学到的东西相近。
- **收益差距主要来自交易假设**，不是模型：QuantLab 每年换手约 37 倍，单边 0.1% 滑点一年就吃掉约 7%，再加佣金和印花税（报告里费用约占 3.7%/年）；
  Qlib 口径没有滑点、买不进就少买一只、按收盘价或开盘价理想成交。把 QuantLab 的滑点设成 0、或在研究台里把费率调高，差距会明显缩小。
- **基准不同**：QuantLab 的等权基准只含满足流动性和上市天数条件的股票，研究台的等权基准是整个「全部股票」池，所以「超额」两边不能直接比，看「设置对照」。
- 这是**模拟数据**上的一次演示，只说明怎么做同数据同区间对比，不说明哪个工具「更赚钱」。

## 交换格式

两边交换实验结果用的 JSON 格式，由本项目定义；QuantLab 1.2.0 的「导出实验结果」按同一格式输出，研究台每次实验也会导出一份（`runs/<编号>/export.json`，报告页「导出对比文件」）。
样例：`samples/quantlab-result-example.json`（数值是随机生成的，只演示格式）。

```json
{
  "format": "quant-experiment-result",
  "format_version": 1,
  "app": "QuantLab",
  "app_version": "1.2.0",
  "run_id": "r20261014_120000_000",
  "name": "LightGBM · 5日 · 前20",
  "created": "2026-10-14 12:00:00",
  "dataset": {"title": "演示数据（模拟 300 只）", "source": "demo", "n_stocks": 300, "start": "2021-01-19", "end": "2026-09-30"},
  "period": {"start": "2022-05-25", "end": "2026-09-29"},
  "settings": {"factors": "…", "n_features": 73, "models": ["lgbm"], "horizon": 5, "top_k": 20,
               "rebalance": "每 5 个交易日", "deal_price": "T+1 开盘价", "costs": "…", "benchmark": "股票池等权"},
  "metrics": {"total_return": 0.12, "annual_return": 0.05, "volatility": 0.21, "sharpe": 0.4, "max_drawdown": -0.18,
              "excess_annual_return": 0.03, "info_ratio": 0.6, "ic_mean": 0.03, "rank_ic_mean": 0.04,
              "icir": 0.3, "rank_icir": 0.35, "turnover": 0.08, "win_rate_daily": 0.52},
  "daily": {"dates": ["2022-05-25", "…"], "return": [0.0012, "…"], "bench_return": [0.0008, "…"]},
  "ic": {"dates": ["2022-05-25", "…"], "ic": [0.05, "…"], "rank_ic": [0.06, "…"]}
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `format` | 是 | 固定 `"quant-experiment-result"` |
| `format_version` | 是 | 整数，目前 1。读取方遇到比自己新的版本会拒绝并提示升级 |
| `app`、`app_version` | 是 / 否 | 产生结果的应用和版本，例如 `"QuantLab"`、`"1.2.0"` |
| `run_id`、`name`、`created` | 否 | 实验编号、名称、时间（`YYYY-MM-DD HH:MM:SS`） |
| `dataset` | 否 | `title` 数据集名称；`source`（demo / tdx / csv / futu / community 等）；`n_stocks`；`start`、`end` 数据区间 |
| `period` | 建议 | 样本外回测区间 `start`、`end`（`YYYY-MM-DD`）；缺省时取 `daily.dates` 首尾 |
| `settings` | 否 | 自由的键值，用于「设置对照」表：`factors`、`n_features`、`models`、`horizon`、`top_k`、`rebalance`、`deal_price`、`costs`、`limit`、`benchmark`、`pool`、`rolling` 等 |
| `metrics` | 建议 | 各自口径的主要指标，**收益一律用小数**（0.05 = 5%），没有的写 `null`：`total_return`、`annual_return`（复利年化）、`volatility`、`sharpe`、`max_drawdown`（负数）、`excess_annual_return`、`info_ratio`、`ic_mean`、`rank_ic_mean`、`icir`、`rank_icir`、`turnover`（日均）、`win_rate_daily` |
| `daily.dates` | 是 | 回测区间内每个交易日，升序 |
| `daily.return` | 是 | 组合**扣费后**的日收益，与 `dates` 等长 |
| `daily.bench_return` | 否 | 基准日收益，与 `dates` 等长；没有就省略或给空数组 |
| `ic.dates`、`ic.ic`、`ic.rank_ic` | 否 | 每个决策日的 IC / RankIC，三者等长（只有其一时另一个给空数组） |

读取方（研究台 `compare.validate`）只依赖必填字段；对比时收益指标由 `daily` 在共同区间上重算，所以各自 `metrics` 的口径不同也没关系。
