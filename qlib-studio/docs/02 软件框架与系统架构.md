## 软件要解决什么问题

Qlib 是微软亚洲研究院开源的量化投资平台，覆盖量化研究的整条链：数据存储与表达式计算 → 因子 → 模型 → 组合策略 → 回测 → 评估。
它的设计面向会写 Python 的研究员：A 股数据要自己准备成它的二进制格式，实验写成 YAML 配置用 `qrun` 跑，结果存在 MLflow 里自己读出来画图。

研究台在不改 Qlib 计算逻辑的前提下，补上桌面用户需要的部分：

1. **数据**：通达信 / CSV / 富途 OpenD / 社区数据集 → Qlib 格式，附质量检查；
2. **实验**：表单代替 YAML，独立进程里运行，有进度、可取消；
3. **报告**：把 Qlib 的回测报告、IC、持仓、成交整理成图表；
4. **对比**：和用户自己的 QuantLab 用同一种交换格式并排比较；
5. **交付**：窗口、使用指南、进程表、缩放、安装包。

## 总体结构

![架构图](<assets/architecture.svg>)

| 层 | 是什么 | 在哪 |
| --- | --- | --- |
| 窗口 | pywebview：macOS WKWebView、Windows WebView2；不可用时改用默认浏览器 | `qlibstudio/app.py` |
| 界面 | 原生 JavaScript + 随包的 ECharts，没有前端构建步骤 | `qlibstudio/web/` |
| 本机服务 | Python 标准库 `ThreadingHTTPServer`，只监听 `127.0.0.1` 随机端口；每次启动一个随机令牌 | `qlibstudio/server.py` |
| 任务管理 | 同一时间一个任务；启动 / 取消 / 查询工作进程 | `qlibstudio/jobs.py` |
| 工作进程 | 同一个程序加 `--worker <任务文件>`；读数据、算因子、训练、回测，结束即退出 | `qlibstudio/worker.py` |
| 数据 | 读取（来自 QuantLab）、富途、社区数据集、Qlib 格式转换、质量检查 | `qlibstudio/data/` |
| 实验 | 调用上游 Qlib 的因子、数据集、模型、IC、回测、风险指标 | `qlibstudio/experiment.py` |
| 对比 | 交换格式的导出、校验、并排计算；QuantLab 1.2.0 导出格式、1.1 实验目录转换成交换格式 | `qlibstudio/compare.py` |
| 上游 | Qlib 0.9.8 源码副本 | `upstream/` |

### 进程

| 进程 | 何时存在 | 做什么 |
| --- | --- | --- |
| 主进程 `QlibStudio` | 应用打开期间 | 窗口 + 本机服务线程 + 任务管理；不做重计算，内存通常 100–300 MB |
| 工作进程 `QlibStudio --worker …` | 有任务时（最多一个） | 导入 / 下载 / 训练 / 回测；大数据集上可能用到几 GB，结束后全部释放 |
| WebView2 子进程（仅 Windows） | 窗口打开期间 | 系统组件，由主进程启动，渲染网页 |
| WKWebView 网页进程（仅 macOS） | 窗口打开期间 | 系统托管（`com.apple.WebKit.*`），不是本应用的子进程 |
| 富途 / moomoo OpenD | 用户自己开着时 | 外部程序，不随本应用启停 |

为什么用独立工作进程：Qlib 的因子计算和模型训练很吃内存，在独立进程里做完就退出，内存一次性还给系统；
「取消」可以直接结束进程，不会卡住界面；上游代码出错（包括 C 扩展崩溃）也不会拖垮主进程。
工作进程和主进程之间不用管道，而是读写任务目录里的文件（`progress.json`、`result.json`、`log.txt`），Windows 无控制台程序也一样可靠。

### 启停与异常收尾

- 正常退出（关窗、⌘Q、Alt+F4、「退出」）：`app.shutdown()` → `Jobs.shutdown()` 先 `terminate`，5 秒不退再 `kill`，连同它的子进程 → 停 HTTP 服务、关闭监听端口。
- 主进程被强制结束：工作进程里的看门狗线程每 2 秒检查主进程的 PID 和启动时间（防 PID 复用），不在了就 `os._exit(3)`。
- 浏览器模式（没有窗口组件）：页面关闭 3 分钟且没有任务在跑时自动退出。

## Qlib 本身怎么工作（研究台用到的部分）

```text
数据目录（provider_uri）
 ├─ calendars/day.txt          交易日历
 ├─ instruments/<池>.txt        股票池：代码 \t 开始 \t 结束
 └─ features/<代码>/<字段>.day.bin   float32：[日历起始位置, 值, 值, …]
        │
        ▼  qlib.data（D.features / 表达式引擎 ops.py，滚动算子由 Cython 扩展 _libs/rolling.pyx 计算）
DataHandlerLP（Alpha158 / Alpha360）
 ├─ QlibDataLoader：把 158 个因子表达式（如 "Mean($close, 5)/$close"）和标签表达式交给表达式引擎
 ├─ infer_processors：推理用的处理（如 RobustZScoreNorm + Fillna），只在训练区间上拟合
 └─ learn_processors：训练用的处理（DropnaLabel、CSZScoreNorm / CSRankNorm 标签）
        │
        ▼
DatasetH(segments = train / valid / test)
        │
        ▼  Model.fit(dataset) / Model.predict(dataset, "test")
LGBModel · XGBModel · CatBoostModel · LinearModel（qlib/contrib/model/）
        │  预测分数（每天每只股票一个数）
        ▼
TopkDropoutStrategy（signal）+ SimulatorExecutor + Exchange（涨跌停 / 停牌 / 一手 / 费用）+ Account / Position
        │  每日报告（return、bench、cost、turnover、account）、持仓、订单指标
        ▼
calc_ic（IC / RankIC）· risk_analysis（年化超额、信息比率、最大回撤）
```

几个要点：

- **表达式即因子**：Qlib 的因子都是字符串表达式（`$close`、`Ref($close, 1)`、`Mean(...)`、`Corr(...)`），由 `qlib/data/ops.py` 的算子类解析计算，按股票逐只算时间序列。Alpha158 的 158 个表达式定义在 `qlib/contrib/data/loader.py`。
- **价格是复权价**，`$factor` 用来在回测里换回真实股数（`Exchange.round_amount_by_trade_unit`）。
- **标签**：Alpha158 默认 `Ref($close, -2)/Ref($close, -1) - 1`，即 t+1 收盘到 t+2 收盘的收益——因为 t 日收盘后算出的预测，最早在 t+1 日成交。研究台按「成交价」和「预测周期」生成同样结构的标签。
- **策略**：`TopkDropoutStrategy` 每天用前一天的预测，卖掉持仓里排名最差的最多 n_drop 只，买入没持有的排名最高的；`hold_thresh=1` 保证至少持有 1 天（满足 T+1）；默认只用 95% 资金（`risk_degree`）。
- **成交**：`Exchange` 按成交价（默认收盘价）成交；`limit_buy / limit_sell` 为真时不能买 / 卖；`$close` 为空（停牌）不能交易；数量凑整到 100 股；费用 = max(成交额 × 费率, 最低费用)。

## 研究台的调用链

### 生成演示数据 / 导入文件

```text
界面「生成演示数据」 → POST /api/job/start {kind: demo}
  → Jobs.start：写 jobs/<编号>/job.json，Popen(QlibStudio --worker job.json --parent <PID>)
工作进程 worker.main → execute("demo")
  → sources.from_demo（QuantLab 的生成器）   或 sources.from_files（readers.scan / read_any）
  → convert.build
       ├─ prepare：复权因子（文件自带 / 已复权 / adjust.estimate_factor）→ 复权价、vwap、change、limit_rate；去掉零成交行
       ├─ 每只写一个 CSV 到 _csv/ → 上游 dump_bin.DumpDataAll（线程池）→ calendars / instruments / features
       ├─ write_pools：stocks、main、chinext、star、bse
       ├─ quality.check：直接读 .bin
       └─ finish_meta：meta.json（区间、股票数、基准候选、股票池）
  → result.json {ok, dataset, summary}；进程退出
界面每秒轮询 /api/status，看到任务结束 → 刷新数据集列表
```

### 运行实验

```text
界面「运行实验」 → POST /api/job/start {kind: experiment, params: {config}}
工作进程 → experiment.run（当前目录临时切到 runs/<编号>/）
  normalize：校验数据集、股票池、区间顺序、参数范围；区间留空时按 6:2:2 自动切
  init_qlib：qlib.init(provider_uri=数据集目录, region=cn, kernels=1)；QlibRecorder.log_metrics → 空函数
  make_handler：Alpha158 / Alpha360（标签按成交价和预测周期；线性模型加稳健标准化 + 填 0）
  逐段（固定切分 1 段；滚动训练按 plan_rolling 切多段）：
      DatasetH(handler, segments) → make_model → fit（记录 evals_result 损失曲线）→ predict("test")
  拼接预测 → calc_ic、group_returns（5 组）
  backtest：TopkDropoutStrategy + SimulatorExecutor + exchange_kwargs（涨跌停表达式、成交价、费用、trade_unit=100）
      → 每日报告、每日持仓（Position）、成交（order_indicator_his → 真实股数 = 复权数量 × $factor）
  summarize：复利口径指标 + 上游 risk_analysis 口径指标 + 每日曲线
  写 config.json、result.json、positions.json、trades.json、pred.csv、export.json（交换格式）
界面 → /api/runs、/api/run?id=…、/api/run/positions、/api/run/trades → ECharts 画图
```

### 富途 OpenD 下载

```text
POST /api/job/start {kind: futu-download, params: {codes, start, end}}（端口来自 settings.json）
工作进程 → futu.download
  parse_codes → "SH.600000" 等；北交所直接拒绝
  Cache：每只算缺的日期段 missing_ranges；全部覆盖 → 不连 OpenD
  real_context：TCP 探测 127.0.0.1:端口 → 线程里建 OpenQuoteContext（最多等 20 秒握手）
  quota（get_history_kl_quota）→ 新请求的股票数 > 剩余额度时停止并说明
  每只每段：request_history_kline（不复权、后复权，各自分页）→ 因子 = 后复权收盘 ÷ 不复权收盘 → 存缓存
  再查一次额度 → series_from_cache → convert.build 生成数据集
```

### 社区数据集

```text
community.download：urllib + Range 断点续传到 downloads/qlib_bin.tar.gz.part，记录发布标签，下完改名
community.import_archive：tarfile（filter="data" 防路径穿越）解压到临时目录 → 找到含 calendars/day.txt 的根
  → 移到 datasets/<编号>/ → write_pools → quality.check（抽查 400 只）→ finish_meta
```

### 与 QuantLab 对比

```text
界面选 QuantLab 导出的 JSON → 浏览器读文件内容 → POST /api/compare/import {content}
  → compare.load / validate（format、长度、日期）→ 存 compare/<编号>.json
勾选若干项 → GET /api/compare?keys=file:…,run:…
  → compare.side_by_side：求共同区间 → 每份在共同区间上重算收益指标 → 净值归一、相对基准、IC 序列
```

## 数据放在哪

全部在用户数据目录（macOS `~/Library/Application Support/QlibStudio/`，Windows `%LOCALAPPDATA%\QlibStudio\`），安装目录只读：

| 路径 | 内容 | 什么时候写 |
| --- | --- | --- |
| `datasets/<编号>/` | Qlib 格式数据 + `meta.json`、`names.json`、`quality.json` | 每次生成 / 导入 / 下载新建一个 |
| `futu-cache/` | 富途日 K 缓存（`<代码>.csv`）和 `index.json` | 富途下载时增量更新 |
| `downloads/` | 社区数据集下载中的文件 | 下载时；导入后默认删除压缩包 |
| `runs/<编号>/` | 实验结果 | 每次实验成功后 |
| `compare/` | 导入的 QuantLab 结果文件 | 导入时 |
| `jobs/<编号>/` | 任务参数、进度、结果、日志、PID | 每个任务；只保留最近 80 个 |
| `settings.json` | OpenD 端口等设置 | 改设置时 |
| `qlibstudio.log` | 应用日志（滚动，最多约 3 MB） | 一直 |
| `webview/` | 窗口组件的本机存储（缩放档位、上次打开的页面等） | 窗口运行时 |

## 安全

- 本机服务只监听 `127.0.0.1`，端口每次随机；所有 POST 请求校验 Host、Origin 和随机令牌（令牌只在启动时放进窗口地址）。
- 文件访问一律走白名单：数据集 / 实验 / 任务编号只允许字母数字和 `_-`；使用指南的文档、源码、附件按清单精确匹配，`../` 不会命中任何文件。
- 社区数据集解压用 `tarfile` 的 `data` 过滤器，拒绝绝对路径、`../`、设备文件和指向外面的链接。
- 富途 OpenD 地址固定为 `127.0.0.1`，界面不能改成别的主机。
- 网页的内容安全策略（CSP）只允许加载本服务的脚本，不连外网。
