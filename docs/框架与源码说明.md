# AI 知识视频工坊 · 框架与源码说明

本文写给要读代码、改代码、二次开发的人。怎么安装和使用见根目录 [README.md](../README.md)。

版本：0.3.1（`studio/__init__.py`）；语言：Python 3.9+ 后端 + 原生 HTML/CSS/JS 前端；运行平台：Windows / macOS / Linux。

---

## 一、整体架构

```
┌──────────────────────── 浏览器页面（studio/web）────────────────────────┐
│ 项目 · 创作 · 分镜 · 审片 · 导出 · 素材库 · 设置 · 说明                 │
│ 原生 JS，无构建步骤；所有请求带启动时生成的令牌 X-Studio-Token          │
└───────────────┬─────────────────────────────────────────────────────────┘
                │ HTTP（只监听 127.0.0.1，随机端口）
┌───────────────▼──────────── 本机服务（studio/server.py）────────────────┐
│ 路由表 → 读写项目 / 设置 / 素材库；耗时操作交给任务管理器               │
└───────┬───────────────────────────────┬─────────────────────────────────┘
        │ 同步：读写 JSON、预览帧         │ 异步：生成 / 改写 / 核查 / 渲染
        │                               ▼
        │                 ┌──── 任务管理（studio/jobs.py）────┐
        │                 │ 同一时间只跑一个任务，可取消、有进度 │
        │                 └──────────────┬────────────────────┘
        │                                ▼
        │       ┌──────────── 生产流水线（studio/pipeline.py）────────────┐
        │       │ 文案：prompts → llm（1 次调用）→ project 规整 → images 配图 │
        │       │ 渲染：textutil 拆句 → tts 配音 → 采样数时间轴            │
        │       │       → visuals 逐句画帧 → media 调 FFmpeg 合成 MP4       │
        │       └─────────────────────────────────────────────────────────┘
        ▼
┌──────────────────── 用户数据目录（studio/paths.py）─────────────────────┐
│ projects/ 项目与导出 · library/ 素材库 · cache/ 模型和配音缓存          │
│ settings.json 公开设置 · private/secrets.json 密钥 · music/ fonts/      │
└─────────────────────────────────────────────────────────────────────────┘
```

设计上的四条主线：

1. **模型只写稿**：默认整条视频只调用 1 次大模型，按固定 JSON 输出标题、分镜、封面标题、简介、标签、事实清单。画面、配音、字幕、合成全部在本机完成，渲染多少遍都不再花 token。
2. **所见即所得**：页面预览和成片用同一个函数 `visuals.render_frame` 画帧。
3. **一切数据先规整再落盘**：模型输出、页面保存、导入的 JSON 都经过 `project.normalize_*`，字段缺失或类型错误时退回能画的默认值。
4. **零第三方 Web 框架**：HTTP 服务用 Python 标准库 `http.server`，必需依赖只有 Pillow、imageio-ffmpeg、certifi 三个，便于打包成免安装程序。

### 技术选型

| 部分 | 选型 | 原因 |
| --- | --- | --- |
| HTTP 服务 | 标准库 `ThreadingHTTPServer` | 不装 Flask/FastAPI，打包体积小，依赖少 |
| 画面 | Pillow 逐帧绘制 | 文字、代码、公式、数字不会画错；跨平台 |
| 视频合成 | FFmpeg（ffconcat 时间线） | 由 `imageio-ffmpeg` 附带各平台二进制，无需另装 |
| 配音 | 系统语音 / 云端 TTS / edge-tts | 默认免费离线；统一转 24kHz WAV |
| 大模型 | OpenAI 兼容 Chat Completions | DeepSeek、硅基流动、通义、Kimi、智谱、火山、Ollama 通用 |
| 前端 | 原生 HTML/CSS/JS | 不需要 Node 构建，改完刷新即生效 |
| 打包 | PyInstaller `--onedir` | GitHub Actions 在 Windows、macOS 上各打一个包 |

## 三、核心流程

### 3.1 生成文案和分镜（调用模型）

入口：`POST /api/projects/{id}/generate` → `jobs.start` → `pipeline.generate`（`studio/pipeline.py:50`）

```
读取 brief（主题、受众、时长、观点、资料）
  │
  ├─ 时长 ≤ 6 分钟：prompts.single_call → llm.chat 1 次
  └─ 时长 > 6 分钟：prompts.outline_call 出大纲 → 每章 prompts.chapter_call 各 1 次
  │
llm.extract_json        容忍 ```json 包裹、前后废话、尾随逗号
  │
apply_generation        写入标题、封面标题、简介、标签、事实清单；
  │                     模型没选精简版镜头时，取开头凑够约 75 秒
project.normalize_scenes 规整每个分镜（见第四节）
  │
images.assign           给 concrete 类配图镜头自动选图
  │
project.save            原子写 project.json
```

省 token 的做法集中在 `llm.chat`（`studio/llm.py:58`）：

- **本地缓存**：`request_key` 对（接口地址、模型、温度、JSON 模式、消息）做 SHA-256，命中就直接返回，不发请求。
- **前缀缓存**：`prompts.SYSTEM` 一字不变放在最前面，DeepSeek 等服务商按缓存价计费。
- **用量记录**：每次调用的 token 数和估算费用写进项目的 `usage`，分镜页顶部显示。
- **容错**：服务商不支持 `response_format` 时自动去掉重试；`max_tokens` 超过服务商上限（400 错误里带上限，如 DeepSeek 的 `[1, 393216]`）时按上限重发一次，任务日志注明；429/5xx 退避重试 4 次；读超时（至少等 600 秒）不重试，免得重复计费；输出被截断时报错并写明最大输出、实际输出和其中的思考 token，截断结果不写缓存。

其他会调用模型的操作：

| 操作 | 函数 | 调用次数 |
| --- | --- | --- |
| 单镜 AI 改写 | `pipeline.rewrite_scene`（:122） | 1 次，带上下镜口播 |
| 事实核查 | `pipeline.fact_check`（:148） | 1 次，可在设置里换成另一个模型 |
| 测试连接 | `server` 里的 `llm_test` | 1 次，max_tokens=20 |

### 3.2 零 token 的两条路

- **粘贴自己的稿子**：`pipeline.script_to_scenes`（:173）按空行分段，规则切分镜：第一段 → 标题卡；``` 包起来的 → 代码卡；连续的 `1.` / `-` 开头行 → 要点列表；短段落里有带单位的数字 → 关键数字卡；其余 → 关键词卡。
- **导入分镜 JSON**：`POST /import_json` → `apply_generation`，格式与模型输出相同，可以在网页版聊天里生成后粘贴。

### 3.3 渲染成片（不调用模型）

入口：`POST /api/projects/{id}/render` → `pipeline.render`（`studio/pipeline.py:255`）

```
① 拆句     textutil.split_chunks：按标点拆成句块，横版每块 ≤26 字，竖版 ≤22 字
② 配音     每个句块 tts.synthesize → 统一转成 24kHz 单声道 16 位 WAV
           缓存键 = 引擎 + 音色 + 语速 + 文本，改一句只重配这一句
③ 时间轴   用 WAV 采样数算每句时长，加句间/分句/镜间停顿（设置里可调）
           字幕 SRT 和画面切换共用这一条时间轴，不会错位
④ 画帧     visuals.reveal_plan 决定每个句块显示到第几条要点、强调哪一条
           visuals.render_frame 画一帧；画面没变就延长上一帧，不重复写文件
           帧时长按帧数量化，累计误差不超过一帧
⑤ 合成     写 timeline.ffconcat → FFmpeg：图片序列 + 配音（+ 循环背景音乐 amix）
           libx264 -tune stillimage，AAC 160k，+faststart；先写 .partial.mp4 再改名
⑥ 附件     SRT 字幕、口播稿.txt、横竖两张封面、发布信息.txt、project-snapshot.json
```

导出目录：`projects/{项目}/exports/{时间}-{landscape|portrait}-{full|short}/`。默认渲染完删除中间文件 `_work/`（设置 `render.keep_work` 可保留）。

取消：`jobs.cancel` 设置取消标志并杀掉当前 FFmpeg/TTS 子进程；流水线在每次 `ctx.progress` 时检查标志。

### 3.4 配图

`images.assign`（`studio/images.py:221`），对应 README 里“配图为什么不容易配错”：

1. 只有 `type=image` 且 `category=concrete` 的镜头才配图（`normalize_scene` 会把抽象概念的配图镜头改成关键词卡）。
2. `images.score`（:168）打分 0–1：英文画面描述按词干匹配图片标签和 alt（权重 0.65），中文标题按二元组匹配（权重 0.35），审片时选过的图额外加分（最多 +0.1）。
3. 最高分低于及格线 `images.min_score`（默认 0.34）就不用图，退回文字卡。
4. 同一条视频内、最近 30 个项目用过的图跳过（`library/usage.json`）。
5. 本地库没有合适的图且开启 Pexels 时，`pexels_fetch` 按英文描述下载图片，连同描述和授权信息存进素材库再打分。
6. 人工选定的图 `locked=true`，重新自动配图时不会被替换。

### 3.5 审片

`GET /api/projects/{id}/review` → `pipeline.review` → `compliance.check` + `compliance.pronunciation_checklist`

- 逐镜规则匹配（`compliance.RULES`）：证券代码、买卖措辞、承诺收益、引流、虚拟货币、医疗、绝对化用语、涉企负面、时效性表述。
- 项目级检查：没填作者观点、没有 quote 镜头、镜头类型过于单一、和最近 20 个项目的镜头结构相似度 > 0.85、低把握度事实未核对、未勾选 AI 声明。
- 读音清单：列出口播里的英文术语和数字，对照“读音替换”表。

## 四、数据模型

### 4.1 项目文件 `projects/{id}/project.json`

由 `project.normalize_project`（`studio/project.py:203`）定义：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | str | `YYYYMMDD-HHMMSS-xxxx` |
| `schema` | int | 数据版本，当前 1 |
| `created` / `updated` | str | 本地时间 |
| `brief` | obj | `topic` 主题、`audience` 受众、`minutes` 时长（0.5–30）、`views` 作者观点、`materials` 参考资料（≤6 万字）、`series` 系列名、`style` 风格要求 |
| `theme` | str | `dark` 深色科技 / `paper` 浅色纸张 / `classroom` 蓝白课堂 |
| `title` / `description` / `tags` | | 标题、简介、标签 |
| `cover_titles` / `cover_choice` | list / int | 候选封面标题和选中的序号 |
| `scenes` | list | 分镜，最多 120 个，见下表 |
| `claims` | list | 事实清单：`text`、`confidence`（high/medium/low）、`note`、`checked` |
| `ai_declared` | bool | 是否勾选“发布时声明 AI 内容” |
| `music_file` | str | 本项目的背景音乐 |
| `usage` | list | 每次模型调用的 token 和费用（服务器维护，页面不能改） |
| `exports` | list | 导出记录（服务器维护） |

### 4.2 分镜 scene

由 `project.normalize_scene`（`studio/project.py:124`）定义：

| 字段 | 说明 |
| --- | --- |
| `id` | `s` + 8 位十六进制，重复时自动换新 |
| `type` | 11 种画面类型之一（见 4.3），未知类型退回 `keyword` |
| `category` | `concrete` 具体事物 / `abstract` 抽象概念 / `data` 数据 / `entity` 人名机构 |
| `heading` | 画面标题（≤30 字） |
| `narration` | 口播原文（≤600 字） |
| `data` | 随 `type` 变化，见 4.3 |
| `image_query` | 英文画面描述，只有 concrete 保留 |
| `image` | `id` 选中的图、`score`、`locked` 人工锁定、`rejected` 点掉的图 |
| `short` | 是否进入竖版精简版 |

缺数据时的降级规则：要点列表没有条目、流程图少于 2 个节点、图表少于 2 个数值、代码为空 → 全部退回关键词卡，保证每个分镜都能画出来。

### 4.3 画面类型与 data 字段

| type | 名称 | data 字段 | 模板函数 |
| --- | --- | --- | --- |
| `title` | 标题卡 | `subtitle` | `visuals.t_title` |
| `bullets` | 要点列表 | `items[≤6]` | `t_bullets`，随口播逐条出现 |
| `keyword` | 关键词卡 | `keyword`、`note` | `t_keyword` |
| `stat` | 关键数字 | `value`、`label` | `t_stat` |
| `code` | 代码 | `language`、`code[≤18 行]`、`highlight[行号]` | `t_code`，语法高亮 |
| `flow` | 流程图 | `nodes[2–6]` | `t_flow`，逐个节点点亮 |
| `chart` | 图表 | `chart`(bar/line)、`labels`、`values`、`unit`、`source` | `t_chart` |
| `compare` | 对比 | `left_title`、`left`、`right_title`、`right` | `t_compare` |
| `table` | 表格 | `headers[≤4]`、`rows[≤6]` | `t_table`，逐行出现 |
| `quote` | 引语/观点 | `text`、`source` | `t_quote` |
| `image` | 配图 | `caption` | `t_image` |

模板注册表：`visuals.TEMPLATES`（`studio/visuals.py:700`）。所有模板签名相同：`(d, img, L, t, sc, ctx, vis, focus)`，其中 `L` 是横竖版自适应的版式（`visuals.Layout`），`t` 是主题配色，`vis` 是显示到第几项，`focus` 是强调第几项。

### 4.4 设置与密钥

- `settings.json`：结构见 `settings.DEFAULT_SETTINGS`（`studio/settings.py`），分 `llm`、`check_llm`、`tts`、`render`、`images`、`pronunciation` 六组。保存时 `_merge` 只接受默认设置里有的键，并按默认值的类型强制转换。
- `private/secrets.json`：`llm_key`、`check_key`、`tts_key`、`pexels_key`。macOS/Linux 上文件权限 600、目录 700。**接口只返回“已设置/未设置”，不会把密钥发给页面。**

## 五、HTTP 接口

所有 `/api/*` 和 `/media/*` 都要求请求头 `X-Studio-Token`（或查询参数 `t`）等于启动时生成的令牌。路由表在 `App._register`（`studio/server.py:47`）。

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/bootstrap` | 版本、平台、设置、密钥状态、FFmpeg、字体、配音引擎、模型预设、音乐列表、当前任务 |
| POST | `/api/settings` | 保存设置和密钥 |
| GET | `/api/voices?engine=` | 列出某个配音引擎的音色 |
| POST | `/api/tts/test` | 试听配音 |
| POST | `/api/llm/test` | 测试模型连接 |
| GET / POST | `/api/projects` | 项目列表 / 新建项目 |
| GET / PUT / DELETE | `/api/projects/{id}` | 读取（附带估算）/ 保存 / 删除到回收站 |
| POST | `/api/projects/{id}/duplicate` | 复制项目 |
| POST | `/api/projects/{id}/generate` | 任务：生成文案和分镜（`fresh=true` 跳过缓存） |
| POST | `/api/projects/{id}/from_text` | 粘贴稿子切分镜（零 token） |
| POST | `/api/projects/{id}/import_json` | 导入分镜 JSON（零 token） |

| GET | `/api/job` | 当前任务状态（进度、消息、日志） |
| POST | `/api/job/cancel` | 取消当前任务 |
| GET / POST | `/api/library` | 素材列表 / 上传图片（base64） |
| POST | `/api/library/import_folder` | 批量导入文件夹（同名 .txt 作为标签） |

## 六、前端结构（studio/web/app.js）

- **令牌**：从地址栏 `?t=` 读取后存进 `sessionStorage`，再用 `history.replaceState` 从地址栏去掉；所有请求通过 `api()` 带上 `X-Studio-Token`。
- **全局状态** `state`：`boot`（bootstrap 返回的信息）、`project`、`estimate`、`sceneId`、`page`、`job`。
- **页面切换** `navigate(page)`：8 个 `<section id="page-*">`，没有打开项目时禁用创作/分镜/审片/导出。
- **自动保存** `scheduleSave` → `saveNow`：改动后 600ms 写盘；保存期间又有新输入时（`editVersion` 变了）保留本地内容并再存一次，不会被旧响应覆盖。
- **分镜编辑**：`FIELDS` 定义每种画面类型在表单里的字段和文本↔数据转换；右侧横竖两版实时预览走 `/preview` 接口。
- **任务**：`onJobStarted` → `pollJob` 轮询（运行中每 0.7 秒，空闲每 4 秒）→ `onJobFinished` 重新加载项目，生成完成后自动跳到分镜页。
- **安全**：所有插入页面的文本经过 `esc()` 转义。

## 七、安全设计

| 风险 | 做法 | 代码位置 |
| --- | --- | --- |
| 其他网页调用本机接口 | 每次启动随机令牌，`secrets.compare_digest` 比较 | `server.py` `_authed` |
| DNS 重绑定 | 只接受 Host 为 `127.0.0.1` / `localhost` | `_host_ok` |
| 局域网访问 | 只绑定 127.0.0.1 | `serve` |
| 路径穿越 | 静态文件、媒体文件、打开文件夹都检查目标在允许的根目录下 | `_static`、`_media`、`reveal` |
| 密钥泄露 | 单独文件、权限 600，接口只返回布尔状态 | `settings.py` |
| 页面篡改用量和导出记录 | PUT 项目时以服务器的 `usage`、`exports`、`created` 为准 | `put_project` |
| 写一半崩溃 | 原子写：临时文件 → fsync → replace | `storage.write_json` |
| 请求过大 | 请求体上限 60 MB | `MAX_BODY` |

## 九、常见二次开发

### 加一种画面类型

1. `project.py`：在 `SCENE_TYPES` 加类型名，在 `normalize_data` 加该类型的字段规整；需要降级时在 `normalize_scene` 加规则。
2. `visuals.py`：写 `t_xxx(d, img, L, t, sc, ctx, vis, focus)`，注册到 `TEMPLATES`；需要逐条展开时在 `scene_items` 返回条目列表。
3. `prompts.py`：在 `SYSTEM` 的“画面类型”里写明用途和 data 结构（会使前缀缓存失效一次）。
4. `web/app.js`：在 `FIELDS` 和 `defaultData` 加表单字段。
5. `tests/test_studio.py` 的 `VisualTests` 会自动覆盖新模板的横竖两版。

### 加一个配音引擎

`tts.py`：在 `ENGINE_NAMES` 和 `available_engines` 注册；在 `TTS._raw` 里加分支，把任意格式音频写到 `raw` 路径即可，后面 `normalize_audio` 会统一转成 24kHz WAV；在 `cache_key` 里加上影响音色的参数。

### 加一个模型服务商

`llm.py` 的 `PRESETS` 加一行（名称、接口地址、默认模型）。只要是 OpenAI 兼容的 `/chat/completions` 就不用改别的。

### 换配图打分

替换 `images.score(scene, entry)`，返回 0–1 的分数即可，例如接入 Chinese-CLIP 做图文向量匹配。及格线、不重复、人工锁定的逻辑都在 `assign` 和 `candidates` 里，不用动。

### 加合规规则

`compliance.RULES` 加一行 `(类别, 严重度, 正则, 说明)`；项目级检查写在 `project_level`。

### 改视频参数

帧率、停顿、片头片尾留白、CRF、编码预设、字幕、水印、背景音乐音量都在设置页（`settings.DEFAULT_SETTINGS["render"]`），不用改代码。
